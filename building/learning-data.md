# 学习信息与存储

长期 Tutor 需要记住一些事情，也需要允许大量日常交流自然留在原处。容量和查询速度只占数据问题的一部分。系统还要理解一条信息从哪里来、能支持什么判断、以后怎样修正，以及它是否真的会改变教学。

当前 Repa 使用本地 SQLite、文件材料和若干类型明确的学习记录。这套实现让身份、版本、事务和恢复获得了可检查的边界，也让我们更清楚地看到尚未解决的问题：哪些学习意义适合结构化，怎样保存模糊判断，怎样从很长的历史中找到当前相关的信息，以及数据模型怎样跟随产品理解继续变化。

## 先问以后要做什么

一条信息值得另行保存，通常因为未来的 Tutor 会用它作出不同选择。例如：

- 知道学习者已经读过某段材料，可以省去重复介绍；
- 知道一次练习在无提示条件下失败，可以帮助 Tutor 选择解释或再次尝试；
- 知道学习者下周有一项重要作业，可以改变近期教学顺序；
- 知道某种解释曾经没有帮助，可以提醒 Tutor 换一种表示；
- 知道学习者主动要求一段时间内不要测试，可以改变后续互动方式。

同一段对话里还有许多无需提炼的内容：临时措辞、已经放弃的思路、普通追问和只服务于眼前的细节。原始 Session 已经保存了它们，后续需要时可以回到来源。

因此，设计一个新字段或实体之前，应先找到它的未来使用者。那个使用者要作出什么决定，原始来源为什么不够，信息经过多久仍然有价值，都会影响合适的表示方式。

## 几种不同的信息

学习过程里经常出现语义相近、作用却不同的内容：

| 信息             | 例子                                           | 后续用途                     |
| ---------------- | ---------------------------------------------- | ---------------------------- |
| 来源与原始内容   | 教材、作业说明、对话、代码、解题过程           | 回到原文、核对语境、继续工作 |
| 观察或报告       | 学习者说读完一节；一次独立作答及其条件         | 记录实际观察到或被告知的事情 |
| 证据             | 作答条件、提示程度、评分结果                   | 支持有限范围内的学习判断     |
| 学习判断         | 某个概念目前仍不稳定；某项操作大致能够独立完成 | 调整解释、练习、回顾和建议   |
| 目标、义务与建议 | 想通过考试；有一项课程作业；近期可以怎样学习   | 组织未来行动和现实取舍       |
| 产物             | 笔记、代码、报告、练习答案                     | 继续编辑、评阅、提交或引用   |

一项写入可以在事务上完全成功，它所表达的认识仍然可能有误。学习者报告、模型判断和直接观察拥有不同依据；修正其中一项时，系统需要保留后来的人能够理解的关系。

这种区分帮助 Tutor 诚实地使用信息。它不要求每次互动都经过完整分类。日常教学可以只留下原始对话；真正进入后续决策的信息再获得合适的结构。

## 原始历史与派生信息

原始材料和对话保存了丰富语境，但不适合每次全部放进模型 Context。派生信息体积更小，容易被发现，却会损失细节，也可能带入解释者的偏差。

Repa 可以把两者连接起来：

```text
原始材料、互动或作品
        ↓ 引用
小而可修正的报告、证据、判断或建议
        ↓ 发现
当前 Context 中的有限索引
        ↓ 按需读取
精确来源和详细内容
```

这个结构允许 Tutor 先看到当前可能相关的内容，再决定是否展开。派生信息要保留回到来源的路径，也要让读者知道哪些文字来自学习者，哪些来自模型，哪些由程序根据可靠事实计算。

摘要并不天然比原始记录更可信。它的价值在于为未来行动提供入口。如果后来发现摘要不合适，可以追加修正、产生新的版本，或者让它退出当前视图。

## 身份、版本和修正

跨时间学习不断产生同名对象和状态变化。课程路线可能修订，材料可能更新，目标会重新表述，学习判断也会随着新表现改变。只保存“当前值”很容易失去来源；把全部历史一股脑交给模型又会制造新的混乱。

当前系统为多类学习信息提供稳定身份和明确版本。修改通常形成新的 revision，并记录它与前一版本及来源的关系。程序可以据此拒绝基于过期状态的写入，模型也能读取当前版本或回看细节。

这种精确性提供了可靠恢复和修正能力，同时增加了 schema、命令、引用和 Context 的复杂度。后续需要继续判断：

- 哪些信息需要稳定身份，哪些只需保留在来源里；
- 哪些变化值得形成新版本，哪些可以作为普通编辑；
- 模型需要看到多少版本关系；
- 历史关系怎样在界面中保持自然；
- 设计怎样允许未来合并、迁移或替换现有记录形状。

版本机制服务于真实修正，不应因为数据库能够保存更多历史就自动扩展。

## 当前存储方案

当前版本在一个本地 LearnerHome 中使用 SQLite 保存 Session 和各类机器状态。课程、Course View、材料引用、目标、未来关注点、作业、学习判断、建议、命令结果和 Context cut 都有相应结构。较大的原始内容可以继续留在文件或内容存储中，数据库保存身份、关系和可检索的元数据。

模型发起修改时，运行时补入真实的 Session、Turn、工具调用、时间和权限；Core 校验版本与合法变化，再在本地事务中提交。新的模型采样会重新读取已经提交的状态。数据库迁移让旧的本地 LearnerHome 能够沿着主线升级。

当前源码和回归测试已经覆盖：模型发起有身份的学习修改，失败返回失败结果，重试返回同一物理调用结果，新 Session 读取跨 Session 的学习信息。直接入口包括 [`packages/opencode/test/learning-command/runtime.test.ts`](../packages/opencode/test/learning-command/runtime.test.ts) 和 [`packages/opencode/test/session/prompt.test.ts`](../packages/opencode/test/session/prompt.test.ts)。分开的记录也保留了课程、证据、作业和建议之间的意义差异。

运行中的压力同样具体：

- 每种新意义会带来 schema、命令、读取、Context 和呈现的联动；
- 精确版本和引用让模型工具参数逐渐复杂；
- 多个独立记录同时影响一次教学选择时，需要跨边界组合；
- schema 一旦进入真实 LearnerHome，后续产品变化要承担迁移成本；
- 当前索引主要依赖明确结构，开放材料和长历史仍需要更丰富的发现方式；
- 存储边界越细，越需要证明这些区分确实改善了后续教学。

目前的关系型设计已经经过认真实现。未来可以调整表的边界，增加文档式或时间式表示，也可以让某些派生内容回到更轻的结构。Tutor 的真实使用方式、修正需求和长期维护成本共同决定下一种形状。

下一轮重构需要明确检验一个边界：来源、版本、修正、撤回、幂等、冲突和 inspection 中，哪些是多类学习信息真正共享的机械语义，可以进入一个共同 mutation boundary；哪些差异仍然属于 Goal、Assignment、学习判断、建议或其他含义自己的 authority。`Learning Record` 可以作为这项研究的工作名称，但目前不是一个已接受的 universal fact owner。字段相似和重复代码本身不足以合并含义，独立 authority 也不要求每类记录继续复制整套基础设施。

候选统一 envelope 必须同时证明两件事：增加一种有真实消费者的记录不会再横跨大量无关位置，且来源、认识状态、合法变化、修正与失败仍能保持原有区别。它与当前 ADR 和实现的具体冲突、升级条件见 [Gate 23 之后的重构方向与冲突记录](../docs/research/repa-post-gate-23-refactor-direction-2026-08-24.md)。

## 检索与 Context

长期数据只有在合适的时候被找到，才会参与教学。Repa 目前采用有限索引加按需精确读取：模型先看到课程、目标、作业、关注点、学习判断和建议中的当前摘要，也会看到遗漏和截断；需要细节时再调用对应工具。

这条路线需要继续研究三种平衡：

1. **发现与容量。** 索引太少，模型不知道该读什么；索引太多，当前请求被历史淹没。
2. **结构与语义。** 明确字段便于可靠过滤，开放文字更能表达学习处境。两者怎样组合会影响检索质量。
3. **相关与私密。** 本地优先减少了外部暴露，但发送给模型的 Context 仍应只包含当前行动需要的内容。

语义检索、向量索引、课程结构、时间窗口和显式引用都可能成为发现机制。它们适合的材料不同，也会产生不同的可解释性和更新成本。Repa 可以把它们作为候选工具，通过真实查询分布判断组合方式。

## 数据生命周期

学习信息可能被修正、替换、撤回、归档或删除。Session 又同时包含学习者文字、模型回答、工具结果和对长期记录的来源关系。删除一段对话时，系统既要尊重学习者的选择，也要诚实处理已经独立存在的课程、目标或作业。

当前实现正在建立 Session 内容、操作记录和独立学习信息之间的边界。更完整的数据生命周期还包括：

- 学习者在删除前看到实际影响范围；
- 本地导出和备份具有清楚语义；
- 旧 schema 可以安全迁移；
- 派生索引能够随来源修正或删除；
- 一个 LearnerHome 可以被完整搬迁或清理；
- 长期保存量和模型可见范围可以由学习者控制。

这些行为会影响存储技术和数据模型，适合与日常使用一起设计，而不是留到发布前再补。

## 怎样继续判断

学习数据的下一步不应以表的数量或查询速度单独衡量。我们需要观察：

- 哪些历史信息真正改变了后续教学；
- 模型能否找到并正确理解它们；
- 学习者纠正以后，后续行为是否随之改变；
- 当前结构是否让新的产品认识难以表达；
- 数据增长后，Context、查询和迁移的成本怎样变化；
- 学习者是否能够理解和控制自己的长期信息。

代表性学习情境、长期真实自用、模型检索实验和数据库迁移测试分别提供不同证据。它们共同帮助我们决定哪些结构应当保留，哪些应当简化，哪些新的表示值得尝试。
