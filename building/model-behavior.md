# 模型行为与 Repa 的形状

Repa 依靠通用大模型完成理解材料、解释、演示、比较、研究和局部教学选择。这些模型经过了广泛的预训练与后训练，熟悉对话、问答、工具调用、代码 Agent 和逐步完成任务。它们没有在 Repa 这套具体产品语义中训练过，也不会天然理解课程位置、未来关注点、学习证据和长期建议之间应该怎样配合。

因此，Repa 的形式必须让模型能够沿用已经熟悉的能力。系统需要把一个长期学习问题投影成模型眼前能处理的任务，同时保留来源、时间、修正和后续学习的连续性。这个投影是否自然，会直接影响模型的教学质量和工具行为。

本章记录当前的工作理解和需要继续验证的问题。不同模型的后训练会变化，Repa 也要根据真实使用更新这里的判断。

## 从长期学习到一次模型行动

通用 Agent 已经熟悉这样一种循环：收到明确请求，查看相关环境，调用具体工具，观察结果，然后继续完成原任务。Repa 可以把一次学习互动组织成相近的形状：

```text
学习者当前的话
+ 最近的原样对话
+ 与当前问题相关的学习背景
+ 可以按需使用的材料和工具
        ↓
模型选择一个当前有用的教学或学习动作
        ↓
解释、演示、提问、读取、修改或协助真实工作
        ↓
观察学习者和工具返回的结果
        ↓
再次判断
```

模型无需理解 Repa 的整个数据库。它需要知道此刻在帮助谁、解决什么、已经有哪些可靠信息，以及还能采取哪些行动。

大模型常见的能力可以承接许多 Repa 行为：

| 模型熟悉的形状               | 在 Repa 中的用途                     |
| ---------------------------- | ------------------------------------ |
| 围绕一条自然语言请求展开工作 | 接住学习者眼前的问题和要求           |
| 阅读文件、网页和工具结果     | 按需读取材料、课程和学习记录         |
| 在多次工具调用后继续原任务   | 查找依据后回到解释、练习或规划       |
| 根据反馈修改答案或方案       | 更换解释、例子、顺序和近期建议       |
| 生成结构化工具参数           | 发起课程、目标、作业或学习信息的修改 |
| 在不确定时询问用户           | 处理真正影响学习方向的选择           |

Repa 应当优先复用这些广泛存在的行为形状。只有当实际失败说明它们无法维持某项产品要求时，新的控制机制才有明确的问题可解。

## 模型为什么容易偏离主线

模型对眼前文字高度敏感。工具返回的新细节、一个有趣的旁支、结构复杂的内部说明，都可能把注意力从学习者原来的问题上拉走。模型还可能沿用其他任务中的习惯：追求一次性完成、不断扩大调查、过早制定长计划，或者把生成测验和总结当成默认的教学收尾。

这种偏离往往不是单句回答明显错误。它可能表现为：

- 局部问题已经得到足够解释，模型仍继续追查背景；
- 读取材料后，回答围绕材料结构展开，忘记学习者问的内容；
- 多个学习事项同时出现时，模型被排在最前的一项吸引；
- 工具调用完成了数据修改，后续文字开始解释内部操作；
- compaction 保留了事实，却丢失了这段对话真正想推进的事情；
- 模型急于完成作业或生成答案，没有给学习者留下需要的认知工作；
- 一条长期建议进入 Context 后，当前请求被当成计划的附属内容。

Repa 需要帮助模型保留主问题：学习者为什么来到这里，这一轮当前在做什么，刚才的读取或子问题怎样服务于它。主问题可能只在当前 Turn 内有效，也可能来自课程、作业或一次约定的回访。跨 Turn 的真实使用会告诉我们是否需要新的持久结构；Context、对话组织和工具反馈则可以先承担当前工作。

## 当前实现提供了什么

当前系统通过三层内容帮助模型进入 Repa：

1. [`repa.txt`](../packages/opencode/src/session/prompt/repa.txt) 描述产品行为和各类学习工具的使用条件；
2. [`LearningContext`](../packages/core/src/learning-context.ts) 在每次交互采样前生成有限的当前视图，并明确哪些内容被省略；
3. `packages/opencode/src/tool/` 中的工具让模型读取细节并发起有约束的修改。

这套办法已经能把课程、材料、目标、作业、未来关注点、学习判断和建议送入普通 Agent 循环，也能让模型的修改经过真实事务。它同时给模型带来了较高的语义负荷：当前模型提示汇集了大量产品规则，Context 包含紧凑编码和多种关系，工具各自拥有详细的适用条件。模型既要正确解读这些内容，又要自然地教学。

这里的取舍需要直接实验。更多规则可以减少某些错误，也可能让模型把注意力放在规则匹配和状态管理上。较轻的结构有利于自然交互，却可能失去来源、边界和恢复能力。程序应处理确定性的部分，模型只接收完成当前语义工作所需的内容。

## Context 应该帮助模型做决定

模型每次采样都需要重新看到学习者的当前请求。最近的原样对话提供语气、指代和刚刚发生的反馈；学习 Context 提供跨 Session 才能获得的背景。二者承担的作用不同。

一个有用的 Context 应当让模型迅速回答几个问题：

- 学习者现在明确要求什么；
- 当前处在哪门课程、哪份材料或哪项真实任务中；
- 哪些早先信息可能改变这一步；
- 哪些内容还需要读取；
- 系统允许采取哪些行动；
- 工具调用以后要回到哪个问题。

容量不足时，Context 要保留发现路径。模型先看到小而可信的索引，再按需读取精确内容。目录顺序、数据库顺序和分页顺序只负责稳定呈现，不能替模型选择学习优先级。

对模型而言，紧凑并不总等于容易。内部编码可以节省 token，但模型需要额外推导才能恢复含义。后续实验应同时观察容量、理解正确率和最终教学行为，而不是只计算 Context 字节数。

## 工具应该延续自然行动

工具名、输入和返回值会塑造模型的下一步。`read material`、`inspect current goal`、`record a learner correction` 这类动作与模型已经熟悉的 Agent 行为接近。一个工具若要求模型同时理解许多内部身份、生命周期和证明条件，模型会把越来越多精力用于协调系统。

程序可以提前绑定当前 Session、Turn、调用身份、时间和权限，让模型只提供真正需要它理解的语义。工具返回应先说明学习者和 Tutor 接下来关心的结果，再保留可供调试和恢复的结构化事实。一个修改已经提交、没有产生变化或发生失败，都要让模型得到明确结果，这样后续回答才能自然继续。

工具数量也会影响选择。大量相似工具容易诱发误选或重复读取。目录、命名和 schema 需要顺着模型的任务分解方式组织，同时保持各类学习信息原有的意义。

## 短程行动与重新观察

Repa 面对的是长期学习，但模型更适合在清楚的局部情境中行动。系统可以采用滚动方式：当前只把下一步做具体，完成后根据新的反馈重新选择。跨日建议也可以保留方向，让临近的行动更清楚，远处留有变化空间。

这种短程行动方式有助于控制偏离。模型无需一次推演整个课程，也不必为几周后的每一天作出决定。它只要理解当前动作怎样服务于更大的学习目的，并在动作结束后回到新的处境。

当学习者打断、纠正或转向时，Repa 应当让新的请求立即成为当前中心。已经提交的事实继续存在，尚未完成的推理不需要被机械重放。新的采样从现有事实和新的话重新开始。

## 需要怎样的模型实验

模型行为的结论不能只从 prompt 推出。Repa 需要在真实学习情境中持续观察：

- 解释过程中插入一个定义问题，模型能否回来完成原解释；
- 连续读取多份材料后，回答是否仍针对学习者的问题；
- 课程、作业、复习和当前请求同时出现时，模型是否作出合理的局部选择；
- 学习者要求换一种解释后，模型是否真的改变方法；
- 工具修改完成后，模型是否自然继续教学；
- 长 Session 经 compaction 后，新的回答是否保留学习主线；
- 学习者几天后回来并报告外部进展时，模型是否重新判断；
- 不同模型在工具选择、追问、计划长度和教学动作上有什么稳定差异。

观察重点包括：当前请求有没有得到回应，模型是否保留主问题，读取和工具调用是否必要，内部状态有没有泄漏到教学文字里，以及学习者是否认为下一步仍然有用。自动检查可以覆盖身份、工具和状态事实；教学选择需要结合成对比较、具体反例和长期真实自用。

随着模型后训练变化，某些提示和工具形状会失去价值，另一些会变得自然。Repa 应当保存产品语义和可观察场景，让模型适配层能够继续演化。
