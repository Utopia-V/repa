## Opening decision and sole control point

Gate 19 is openable, but only in the narrowed form below.

The current accepted control point is one collision caused by an already legal
source lifecycle: after an Interaction-owning Session is deleted, Gate 18 keeps
the exact root-Turn/occurrence locator and truthfully reports
`source_unavailable`, while independent domain meaning may survive. A fresh
Session can still read the exact criterion material, Course/navigation, Goal,
steering, Material/current-use state, and all ordinary Gate 18 projections, but
it cannot reconstruct the deleted learner response or whether the response
preceded decisive Tutor disclosure. Two histories can therefore have equal
current state at every existing owner and require different next Tutor moves.

The admitted invariant is:

> When a completed current learner response is intentionally promoted because
> a later Tutor move will consume its relation to the entire byte range of one
> exact immutable Material Map selector, under one narrowly earned disclosure
> condition and one exact Course membership target, Repa preserves a bounded,
> fallible, source-linked, correctable evidence assessment. The neutral
> alignment is admission provenance, not criterion meaning. Deleting the source
> Session may make the response and condition sources unavailable but must not
> silently turn the assessment into mastery, erase its correction history, copy
> source bodies, or force every teaching interaction to write.

Decision ID `G19-OPEN-001`. Revision owner: this Gate contract until accepted;
after acceptance, the product/architecture owner for challenged meaning and
this contract for Gate-local mechanics.

## Parent problem and strongest counterexample

The parent question is not “what learner schema should Repa have?” It is:

> What minimum source-linked distinction must survive into a later Turn or
> fresh Session to change one later Tutor action when the raw response can no
> longer be read, while preserving correction and leaving valuable zero-write
> teaching legal?

The strongest counterexample to this Gate is the source-readable control. If
the exact learner response, its eliciting/disclosure order, and exact historical
criterion remain available, Gate 18 plus ordinary Agent reasoning can derive a
move-local judgment. No durable learner record is needed. Source composition,
tests, or a model's confidence cannot defeat that ablation.

The positive counterexample to “Gate 18 is always sufficient” is fixed by the
[exact bounded result](repa-gate-19-source-unavailable-collision-result-2026-08-05.md).
It holds every existing durable learning owner byte-equivalent and varies only
a deleted response/disclosure pair that was deliberately assessed while still
available:

| History | Promoted evidence while source was readable | State after source Session deletion | Required later move |
| --- | --- | --- | --- |
| `S` | response supports the entire exact selector proposition; response occurred before decisive Tutor disclosure | exact response locator is `source_unavailable`; criterion and all existing Gate 18 state remain equal | continue, deepen, or apply without claiming mastery |
| `N` | response does not support the same entire selector proposition; same disclosure condition | same existing state as `S` after opaque identity normalization | correct or reteach the criterion before progressing |
| `D` | byte-identical response to `S`, but Tutor disclosed the decisive answer before the response | same existing state as `S` after source deletion | do not treat the response as answer-hidden evidence; offer a new answer-hidden opportunity if useful |

Without the promoted assessment,
`projection(S) = projection(N) = projection(D)` after the source becomes
unavailable, while their required move families differ. Keeping a hidden
transcript copy would defeat accepted Session deletion. Regrading current
material cannot reveal deleted response or disclosure order. An unsupported
mastery scalar would answer a different question.

The exact fixture selector targets the 101 UTF-8 bytes
`The inherited Agent loop is\nthe ordinary execution substrate, not the
long-term learning-state model.` (where `\n` denotes the one literal LF) at
zero-based byte range `[12033,12134)` of
[product origin](../foundation/00-product-origin.md).
The observed file SHA-256 is
`c32f085427d5e316904d76a4cff6e597b9dd3afc880d9d4b656af7062521f16d`;
the selector witness SHA-256 is
`54fe411f18c36865df640ffbb92e1aabd959fdaf1bf380a3d782e757ae1a761d`.
Those hashes make the experiment reproducible, not a runtime identity rule.
Production identity binds an admitted Artifact Revision and its immutable Map
selector. The neutral alignment only proves an exact Course endpoint connection.

Decision ID `G19-COLLISION-001`.

The exact result fixes literal response/disclosure/current-request bytes, an
exact selector/alignment fixture, a canonical byte-identical existing-owner
projection after deletion, and mutually exclusive later actions. The oracle is
falsified if any current accepted read recovers the raw response and disclosure
condition after Session deletion without preserving prohibited bytes, or if one
later action is equally honest, useful, and compliant across the three
histories. In either case the record boundary must shrink or be removed.

Decision ID `G19-EXPERIMENT-001`.

## Admitted meaning: response evidence, not occurrence or inference

Interaction and Gate 8 already own the occurrence: the admitted learner input,
its source order, Session/Turn/Message identity, presentation, deletion
tombstone, and physical tool invocation. Gate 19 does not create another
activity or occurrence table.

Gate 19 adds one `LearnerResponseEvidence` authority. One record means:

> For the entire exact byte range of one immutable Material Map selector, under
> the recorded disclosure condition and one exact Course membership target, the
> current fallible assessment says whether one completed learner response
> supports or does not support that selected proposition/text.

The relation always applies to the selector's entire exact byte range. Gate 19
does not store or key a second Agent-authored criterion claim. If a selector
contains several independently assessable claims, the Agent must create no Gate
19 effect for a subclaim; a separately admitted finer immutable selector is
required first. The neutral alignment does not become `assesses`, `evidence`,
or pedagogic truth.

The record is an authored evidence judgment. It is not a program proof that the
claim or condition is true. A successful tool call establishes only that the
authorized Agent authored and the runtime legally committed that exact
assessment with exact provenance.

The first revision vocabulary is closed:

- relation: `supports` or `does_not_support`;
- assessment basis: `tutor_interpretation` or `learner_report`;
- answer-exposure condition: either
  `learner_response_before_tutor_disclosure` or
  `tutor_disclosure_before_learner_response`; and
- disposition: `active` or `retracted`.

These are closed stored values, not freely interchangeable payload fields.
The legal operation/basis/source matrix below fixes when each basis may be
created or revised. In particular, revision `0` is always
`tutor_interpretation`; `learner_report` is earned only by an explicit
source-bearing correction revision; and retraction preserves rather than
relabels the current assessment basis.

`supports` means only “this source occurrence supports the proposition/text in
this entire exact selector under these recorded conditions.”
`does_not_support` does not prove a general deficit. Ambiguous relation,
multi-claim selector, or unestablished disclosure order produces no record or
revision; uncertainty is not encoded as durable activity. The answer-exposure
condition records one earned semantic distinction; it is not a universal
independence, assistance, hint, or assessment taxonomy. The runtime validates
identities, completion, source order, and legal references, but ordinary Agent
interpretation owns whether cited Tutor text disclosed a decisive answer.

No inference or hypothesis record is admitted. In particular, the authority
stores no mastery, understanding, retention, ability, misconception,
prerequisite, confidence, score, probability, difficulty, progress, review
priority, recommended move, or planned action. A later Tutor may form a local
hypothesis from the evidence and current situation; that hypothesis stays in
Interaction unless a later consumer separately earns durable meaning.

Decision ID `G19-MEANING-001`.

## Identity, source, and revision contract

### Semantic identity

One evidence record has a stable generated ID and one immutable semantic
effect address:

```text
subject learner occurrence ID
+ exact (MaterialMapID, MaterialSelectorID)
+ exact (CourseID, ViewID, CourseViewRevisionID, CourseItemID)
```

This is the command-owned domain slot required by ADR-0009. The Map fixes the
exact Artifact or Representation Revision, selector coordinate, and witness;
the Course tuple fixes exact immutable membership. Gate 19 stores those
references, not selector or response bytes. One exact Gate 13 alignment must
prove that the two endpoints are neutrally connected at creation, but its
opaque ID and reason are provenance rather than criterion/effect identity. Two
independent alignment rows for the same endpoints therefore do not create two
evidence slots, and one alignment cannot hide several subclaims.

Creation is intentionally restricted to the current root learner response of
the issuing interactive Turn. The runtime binds that response's occurrence ID;
the model does not type or invent it. This first boundary does not authorize
retroactive transcript mining, artifact assessment, bulk import, or arbitrary
historical promotion.

For one semantic address:

- exact physical replay returns Gate 8's stored settlement;
- a later physical invocation with the same canonical active payload returns
  `already_applied` without a new revision and without replacing the first
  admission's provenance;
- a different payload conflicts and must name the existing record and expected
  current version through the correction transition; and
- a different selector endpoint or exact Course membership is a different
  semantic address, never an implicit correction. A different alignment proof
  for the same endpoints is not a different address.

Opaque IDs carry no assessment meaning. Tool invocation ID, model/provider ID,
or source time is not semantic learner-record identity.

### Immutable source basis

Each record/revision preserves:

- the subject learner occurrence ID and its immutable source-order identity;
- the exact Map/selector and Course/View/revision/item endpoints resolved at
  creation, plus the exact neutral alignment used as admission provenance;
- the relation, assessment basis, answer-exposure condition, and exact
  eliciting/disclosure Assistant Message locator when the condition cites one;
- the domain revision/effect identity, runtime-bound current causal learner
  occurrence that caused each command, issuing model operation and physical
  invocation provenance supplied by Gates 8 and 12, trusted commit time, and
  shared-frontier coordinate;
- assessment-basis source separately from command cause: the exact available
  subject/elicitation/disclosure sources for `tutor_interpretation`, or the
  runtime-bound current learner correction occurrence for `learner_report`; and
- the predecessor revision and expected prior version for every correction or
  retraction.

Command cause answers why this revision was attempted; assessment-basis source
answers what epistemic source warrants its stored label. One never substitutes
for or silently relabels the other.

No model-authored criterion claim, rationale, prompt, or action prescription is
stored. At preparation, current-use resolution must yield a nonempty selector
of at most 2,048 UTF-8 bytes; the evidence relation applies to that entire exact
range. A wider or semantically multi-claim range is zero-write until a finer
selector is independently admitted. Aggregate command and owner-read limits
remain explicit and must fail before a partial write.

At creation the runtime validates that the occurrence is the available,
complete current learner source; the Map/selector and Course endpoint form one
accepted exact target connected by the named neutral alignment; the alignment
and Map are active; the selector is nonempty, within the Gate 19 bound, and
current-use eligible under the existing owner rules; and cited Assistant
Message locators are complete, belong to the allowed current Interaction
lineage, and have legal source order. These checks do not prove the open-language
relation or disclosure semantics.

For `learner_response_before_tutor_disclosure`, the record cites the exact
answer-hidden eliciting Assistant Message that precedes the response. For
`tutor_disclosure_before_learner_response`, it cites the exact decisive
disclosure Assistant Message that precedes the response. Whether the first is
answer-hidden or the second is decisive remains a fallible Agent interpretation;
the runtime proves only exact identity, completeness, lineage, and order.

After creation, source correction, withdrawal, drift, or unavailability never
retargets the record. Reads show both the immutable recorded locator and its
current availability/relation where the owner can derive one. Missing response
or Tutor text returns `source_unavailable`; it never falls back to a similar or
latest Session. Missing criterion backing fails closed for exact content reads;
the stored fallible assessment remains inspectable with that limitation.

Decision ID `G19-SOURCE-001`.

### Revisions and correction

Revision `0` creates one active assessment. Every later change appends exactly
one revision under an expected current version. Operation, stored basis, and
admissible basis source obey this closed matrix:

| Operation | Caller-supplied assessment fields | Program-bound basis and required source shape | Result |
| --- | --- | --- | --- |
| `create` | relation, disclosure condition, exact target/provenance references; no basis or disposition field | basis is `tutor_interpretation`; the exact current complete subject response and cited answer-hidden elicitation or decisive disclosure are all currently readable and admissible | create active revision `0` |
| `revise_from_tutor_interpretation` | expected version, relation, disclosure condition; no basis, disposition, or replacement source ID | basis is `tutor_interpretation`; the runtime revalidates that the immutable subject response and every cited condition source needed to reinterpret it remain exactly readable, complete, and admissible | append an active revision and, if needed, reactivate |
| `revise_from_learner_report` | expected version, relation, disclosure condition; no basis, disposition, or caller-chosen report source ID | basis is `learner_report`; the runtime binds the available current root learner Input as the distinct correction source and records that report provenance | append an active revision and, if needed, reactivate |
| `retract` | expected version only; no relation, condition, basis, or disposition field | preserve the current relation, disclosure condition, assessment basis, and basis-source provenance; bind the current causal occurrence only as retraction provenance | append a retracted revision without relabelling the assessment |

No generic `revise` accepts a freely chosen basis. A
`revise_from_tutor_interpretation` after any required observation source becomes
unavailable is illegal even if a current learner correction message exists. A
`revise_from_learner_report` never claims independently observed performance;
the runtime proves that the report source is the current learner Input, not that
its open-language content is true. An illegal operation/basis/source shape
fails before the evidence revision and learning-command effect commit.

The current head is a program-owned pointer protected by optimistic concurrency
and database constraints. Stale expected versions reject. Competing writers
cannot produce two current heads, silently merge assessments, or use
last-write-wins.
The correction's current causal learner occurrence and Agent/tool provenance
are stored alongside—not instead of—the basis source. `learner_report` records
evidential strength and does not upgrade the report to observed performance. If
a correction changes the proposition/selector or exact Course target, it is not
a revision of this slot. The old record may be retracted and a separately
eligible new effect may be created.

Correction never edits the Interaction transcript, Course, Map, selector,
alignment, Goal, navigation, future attention, plan, or prior context cuts.
Old Tutor responses and cuts retain the evidence revision they actually saw;
the next admitted model operation observes the new owner-read head. It receives
that head automatically only if the unavailable-source eligibility rule is also
true; while a `learner_report` correction's basis source remains readable, Gate
18 Interaction context retains derivation priority. A command-cause occurrence
that supplied no assessment meaning is provenance, not an automatic-pressure
disqualifier.

Decision ID `G19-REVISION-001`.

## Command, capability, and settlement boundary

One versioned Agent-facing write capability exposes a closed single-operation
command:

- `create` for the current learner response, one exact Map/selector endpoint,
  one exact Course membership endpoint, and one neutral alignment proof;
- `revise_from_tutor_interpretation` for one exact record/current version while
  every required original observation source remains readable;
- `revise_from_learner_report` for one exact record/current version from the
  runtime-bound current learner correction source; or
- `retract` for one exact record/current version.

The command uses Gate 8's shared occurrence, physical invocation, capability,
permission, semantic settlement, replay, and receipt substrate. The runtime
binds LearnerHome, current Session/Turn/model operation, current causal
occurrence, source order, time, capability catalog/policy, and exact tool
version. The model supplies only the allowed semantic payload and owner
references visible through context or owner reads. It never supplies the stored
basis, disposition, current causal occurrence, basis-source occurrence, or a
replacement subject/selector/Course identity; the operation variant and runtime
derive or bind them.

Root and delegated Agents require explicit capability membership and the
configured `allow`/`ask`/`deny` policy. Restricted/custom Agents remain
default-deny. A permission decision is not evidence meaning. A denied,
cancelled, malformed, stale, conflicting, or required-basis-source-unavailable
candidate creates no domain revision. Original response deletion does not by
itself invalidate `revise_from_learner_report` when its distinct current report
source is available; it does invalidate observation-based create/revision.
Agent issuance, policy settlement, domain effect, and typed terminal result
remain distinguishable.

Domain revision/effect and learning-command settlement commit atomically in the
LearnerHome database. A crash before commit creates neither; a crash after
commit replays the exact terminal result and never reapplies the revision.
Provider or presentation failure after commit cannot hide or undo the durable
effect; retained carriers use the existing typed settlement presenter.

The write is optional. No successful explanation, reading, tool result,
assessment-like question, learner answer, Turn completion, Session end, or
source deletion automatically invokes it. There is no background inference or
write path. The tool description must state the positive later-consumer
threshold and the zero-write default.

Decision ID `G19-COMMAND-001`.

## Reads and Gate 18 context extension

`LearnerResponseEvidence` owns one pure, cursor-bounded read surface:

- list current records for one exact Course/View-revision/item or exact
  Map/selector endpoint;
- read one current record by ID; and
- read one record's revision history.

One result returns at most 64 typed items and 32,768 UTF-8 bytes, with an exact
cursor and truthful truncation. It returns assessment meaning and locators, not
raw response, Tutor, or selector bytes. Interaction and Material reads remain
the only routes to those bodies and retain their own authority, permission,
current-use, availability, and size rules.

Gate 19 extends Gate 18 through a new versioned producer contribution; it does
not mutate an old cut or create another context database. Automatic pressure is
restricted to the experimentally earned unavailable-source control point. For
every newly admitted interactive model operation, a candidate qualifies only
when all of these conditions hold:

- its current disposition is `active`;
- its exact Course/View-revision/item is already structurally included by the
  Gate 18 Course/navigation/material cut;
- the subject learner response exact read reports
  `source_unavailable`/`source_deleted`; every cited elicitation/disclosure
  locator needed for the recorded condition is in the same truthful unavailable
  state; and, when the current basis is `learner_report`, its distinct report
  source is unavailable too. Any available assessment-basis Interaction body
  from which the current relation, basis, or condition can be honestly
  rederived disqualifies automatic pressure; a command-cause-only occurrence
  does not; and
- the exact Map/selector and neutral Course alignment remain current-use
  eligible and the selector still resolves and witness-verifies within the Gate
  19 byte bound. Unavailable, drifted, withdrawn, superseded, or ineligible
  criterion backing disqualifies automatic pressure rather than retargeting it.

Among qualifying candidates:

- automatic context may include at most eight current heads;
- candidates are ordered deterministically by subject source order and opaque
  ID, not by mastery, importance, confidence, predicted utility, or a host-side
  semantic score;
- coverage, eligible count, omission, current revision, exact source
  unavailability, and current target relations are truthful;
- retracted and source-readable records remain inspectable through the owner
  read but are absent from automatic pressure; and
- if a qualifying head is outside the bounded page, the cut says so and the
  ordinary Agent may use the owner read. Cropping never means absence.

The evidence contribution is compiled in the same transaction and under the
same immutable operation cut as the other Gate 18 producers. Owner correction
after admission does not rewrite that cut. A domain write during a Turn becomes
visible only to a newly admitted provider operation. Retry of one operation
reuses its original cut.

The protected rendering labels every relation as a source-linked fallible
assessment of the entire exact selector, includes the basis and disclosure
condition, states `source_unavailable` exactly, and says explicitly that the
record does not establish mastery, understanding, retention, correctness beyond
that selector-bound occurrence, or a required next action. The ordinary Agent
still chooses the move.

Fresh Session, resumed Session, explicit fork, child, steer, tool continuation,
post-compaction continuation, structured output, native adapter, AI SDK,
direct-run, TUI, attach/server, and ACP retain Gate 18's applicability rules.
Internal title, compaction, representation, project-name, Agent-generation, and
other narrow internal model operations receive no learner-evidence block.

Decision ID `G19-CONTEXT-001`.

## Session deletion, failure, and recovery truth

| Condition | Required result |
| --- | --- |
| source Session remains readable | exact Interaction and Material reads remain available; the Agent may derive locally and is not forced to create or trust a durable assessment; any record remains owner-readable but absent from automatic context pressure |
| source Session is deleted after an evidence commit | normal transcript bodies and presentations follow accepted deletion; referenced occurrences/locators retain tombstones; the evidence record survives as an independent domain effect and reports `source_unavailable`; it qualifies for automatic pressure only if every other context condition remains true |
| source Session is deleted before `create` or `revise_from_tutor_interpretation` commits | required observation-source validation fails; no evidence revision or settlement claiming an effect. A separately valid `revise_from_learner_report` may still use its available current report source without claiming observation |
| selector source or neutral alignment drifts, is withdrawn, is superseded, or becomes unavailable | immutable recorded identities remain; no latest/similar retarget; exact body read fails closed and owner reads show current relation/availability without rewriting the assessment; automatic pressure is absent |
| cited Tutor message is absent, incomplete, from another unauthorized lineage, or ordered illegally | candidate fails before domain commit |
| `create` supplies `learner_report`, any basis, or any disposition | strict operation decoder rejects; revision `0` can only receive program-bound `tutor_interpretation` and `active` |
| `revise_from_tutor_interpretation` cannot exactly read the immutable subject or every required condition source | candidate fails before domain commit; an available learner correction cannot be relabelled as Tutor observation |
| `revise_from_learner_report` supplies a historical, Assistant/tool, cross-LearnerHome, or caller-chosen report source | candidate fails; only the runtime-bound available current root learner Input may be the report basis source |
| `retract` attempts to change relation, condition, basis, or basis source | strict operation decoder rejects; a legal retraction preserves the prior assessment fields and adds only retraction disposition/provenance |
| relation, whole-selector meaning, or disclosure order is ambiguous | create no record or revision; adapt conversationally without a write, or ask only a genuinely necessary learner-owned clarification; never fabricate precision |
| correction races another revision | one exact expected version wins; the stale candidate fails with the current locator and no partial state |
| duplicate semantic create has identical current payload | return already-applied truth; no duplicate record or revision |
| duplicate semantic create differs | return semantic conflict and require explicit revision; no competing current head |
| permission is denied/cancelled or provider fails before the tool call | no evidence effect |
| provider/presentation fails after committed tool settlement | evidence effect and typed terminal settlement remain durable and inspectable; no blind replay |
| application restarts after commit | current head, history, source availability, and exact settlement recover without resampling or rewriting |

Session deletion must not preserve transcript or selector text in the evidence
row, context cut, tool receipt, command payload, error, log, or migration
artifact. Keeping immutable owner references, the binary relation, basis, and
condition is not a hidden transcript copy; those are the explicitly admitted
independent domain meanings. If this distinction cannot be maintained in
implementation, the Gate must be rejected rather than weakening deletion truth.

Decision ID `G19-FAIL-001`.

## Ownership and dependency direction

The new authority belongs in Core beside the other native learning authorities,
not inside the Agent runner, prompt layer, Session tables, Material Map, Goal,
or a universal learning-state aggregate.

```text
Interaction occurrence/tombstone -----> LearnerResponseEvidence
Material Map exact selector ----------> LearnerResponseEvidence
neutral alignment admission proof ----> LearnerResponseEvidence provenance
Course/View immutable target ---------> LearnerResponseEvidence
Gate 8/12 command provenance ---------> LearnerResponseEvidence revisions
LearnerResponseEvidence pure view ----> Gate 18 context + owner read tool
Gate 18 context ----------------------> ordinary released-v1 Agent
```

Dependencies point from the evidence owner to stable identities owned by
Interaction, Course, and Material. Those owners do not depend on or mutate
learner evidence. Gate 18 coordinates a pure projection; it does not become the
record owner. Opencode binds tools, permissions, model-visible descriptions,
and presentation over Core commands/reads. Low-level provider and carrier code
remains domain-independent.

The implementation may add versioned native tables, strict decoders, database
constraints/triggers, a Core domain module, one write tool, one read tool, and
the Gate 18 versioned producer/renderer extension. It must not add a generic
manager/service/repository/controller, universal learner/activity/event/fact
