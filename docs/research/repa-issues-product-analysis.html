Repa 到底是什么？

一个本地优先的长期学习 Agent。 它不强迫学习者进入课程流程，而是让人像使用普通 Agent 一样提问；当问题需要长期语境时，再调用最新目标、资料、计划和历史，帮助学习者做出下一步。

这份页面把仓库 Issues、README、CONTEXT 和当前测试压缩成一张可浏览的产品地图。黄色标签表示基于证据的推断或建议。

一句话定位

把“今天的问题”连接到“长期正在发生的学习”。

普通 Agent 往往只看当前提示，容易忘记多个目标、期限、现实限制和不断加入的材料。Repa 要减少学习者在安排、检索、整理、回顾和重新规划上的额外负担，同时让长期数据仍归学习者自己拥有。

产品的四个原则

它们决定哪些功能应该进入 Repa，哪些功能即使有趣也不应改变产品边界。

Issue #5

当前请求优先

普通聊天不必自动产生长期记录；只有当前请求需要时，才规划、整理、回顾或读取历史。

Issue #6

最新状态压过旧对话

目标、期限和可用时间会变化。旧 Session 是过去发生过什么，不是现在应该依据什么。

CONTEXT / ADR

学习者拥有数据

持久学习数据保存在本地空间；Wiki 等资产可以直接打开、修改、核验，远程模型只接收当前选择的上下文。

Issue #3

Agent 辅助，不替学习者裁决

Agent 可以建议、出题、评价回答和指出偏离，但掌握判断和是否继续探索仍由学习者决定。

最可能的用户是谁？

这里既有 Issue 明确写出的用户边界，也有从当前 CLI 形态推出来的早期采用者画像。

明确方向

自驱型、长期学习的学习者

他们通常同时有多个目标，会积累 Markdown 笔记、课件、试卷或个人知识库，且时间和目标会变化。可以是备考者、工作技能学习者或长期兴趣学习者，不要求正式学生身份。

推断：早期采用者

愿意管理本地文件和模型配置的人

当前产品要求指定本地目录、配置 Pi provider，并通过最小 TUI 使用。因此第一批用户可能更偏技术熟悉、重视本地所有权和可审计性的学习者。

理想的产品闭环

长期价值不在于“记住所有聊天”，而在于每次只把当前真正需要的长期语境带进来。

01 · ASK

学习者提问

像普通 Agent 一样问概念、计划、资料或进展。

02 · GROUND

读取当前状态

先拿最新目标、期限和现实限制，避免被旧 Session 带偏。

03 · COMPOSE

按需取相关材料

只加载相关计划、Wiki、来源或历史片段。

04 · ACT

回答或提出修改

Agent 理解意图；程序检查可计算的约束和版本。

05 · OWN

结果归学习者

写入可见、可修正、可恢复；下一次学习继续复用。

现在做什么，暂时不做什么

这个对照能防止产品从“长期学习助手”滑向“课程管理系统”。

现在应该做

  • 普通对话和学习请求共用一个 Agent 核心。
  • 当前目标和限制始终使用最新版本。
  • 按需读取资料、历史、计划和 Wiki。
  • 写入有通知、有版本、有冲突处理。
  • 本地文件是学习者可带走的资产。

暂时不要做

  • 固定课程路线或强制教学状态机。
  • 后台 scheduler、主动提醒和自动唤醒。
  • 自动把正确率变成掌握分数。
  • 先建复杂知识图数据库再验证视觉价值。
  • 把“本地优先”误写成“完全离线”。
