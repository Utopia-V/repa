# DeepSeek staged-model collaboration experiment

Date: 2026-07-11

Status: Research observation for ALS-011. This document does not select a
permanent provider, router, escalation policy, or multi-agent architecture.

## Question

Can one learning interaction use **DeepSeek-V4-Flash (API, non-thinking)** for
cheap evidence reading and **DeepSeek-V4-Pro (API, thinking=max)** for a
consequential learning-action decision without inventing a second agent
runtime?

Two materially different meanings of "model collaboration" were tested:

1. switch models between steps of one existing tool-call history; and
2. end the first call, pass a small provenance-bearing evidence packet, and
   start a fresh second call.

ChatGPT GPT-5.6 Pro (subscription, Extended Pro via the private Pro bridge) was
not consulted for this batch.

## Experiment A: switching models inside one tool history

`labs/deepseek-learning-loop/staged-model.ts` uses AI SDK `prepareStep.model`
to compare:

- DeepSeek-V4-Flash for every step;
- DeepSeek-V4-Pro for every step; and
- DeepSeek-V4-Flash for the read step, followed by DeepSeek-V4-Pro for the
  decision and continuation steps.

The same learning contract applied to all three profiles: a correct attempt
completed with a hint and without a delayed independent pass requires a
verification action. No durable learning write was exposed.

The two single-model profiles passed their one-trial diagnostic runs. The
mixed profile failed before making the decision:

```text
AI_APICallError: The `reasoning_content` in the thinking mode must be passed
back to the API.
```

| Profile | Contract result | Mean model steps | Input tokens | Reasoning tokens | Elapsed |
|---|---:|---:|---:|---:|---:|
| DeepSeek-V4-Flash only | pass | 3 | 1,459 | 0 | 4,099 ms |
| DeepSeek-V4-Pro only | pass | 3 | 1,920 | 240 | 8,339 ms |
| DeepSeek-V4-Flash then DeepSeek-V4-Pro in one history | protocol failure | 0 completed | 0 recorded | 0 | 742 ms |

The failed path is retained in the local Git-ignored trace
`2026-07-11T02-43-57.620Z-staged-deepseek-model-collaboration.json`.

### Cause

The failure is not evidence that AI SDK cannot override a model per step.
That mechanism did select the requested model. The provider history was the
problem.

The previous assistant tool call had been generated by non-thinking
DeepSeek-V4-Flash and therefore had no reasoning part. DeepSeek-V4-Pro thinking
mode required the previous assistant tool-call message to include
`reasoning_content`. The installed OpenAI-compatible adapter serializes a
reasoning part back as `reasoning_content` when one exists, but it cannot
truthfully synthesize reasoning that the first model never produced.

Therefore, a library-level per-step model override is not by itself a portable
cross-model continuation contract. Provider message-history requirements must
also agree.

## What pinned OpenCode actually does with a small model

Pinned OpenCode commit `b1fc8113948b518835c2a39ece49553cffe9b30c` contains
`getSmallModel`, but the studied call sites do not switch the active model in
the middle of a tool chain:

- `packages/opencode/src/session/prompt.ts` uses a small model in a separate,
  tool-free call to generate the session title; and
- `packages/opencode/src/server/routes/instance/httpapi/handlers/project-copy.ts`
  uses a small model in a separate, tool-free call to generate a project-copy
  name.

This is evidence for isolated helper calls, not evidence that OpenCode routes
different models through one shared tool history.

## Experiment B: isolated provenance-bearing handoff

`labs/deepseek-learning-loop/isolated-model-handoff.ts` created a synthetic
620-line, 71,336-character attempt log. It contained an archived distractor and
one authoritative active attempt. The correct active facts were:

```text
sourceRef=session-item:attempt-log-staged-v1
attemptId=attempt:isolated-handoff-1
target=binary-search-loop-invariant
outcome=correct
assistance=hint
delayedIndependentCheckPassed=false
```

Three profiles were compared:

1. DeepSeek-V4-Flash read the full log and decided directly;
2. DeepSeek-V4-Pro read the full log and decided directly; and
3. DeepSeek-V4-Flash extracted the six-field evidence packet, then a fresh
   DeepSeek-V4-Pro request decided from only that packet.

The third profile shared neither provider tool-call history nor an agent
runtime. It was two ordinary model calls joined by an explicit data boundary.
The executor still owned the learning rule and no durable state write was
available.

### Repeated result

All three profiles passed all three repeated trials. Every isolated extraction
preserved the exact source reference and evidence fields, and every profile
selected `verification`.

| Profile | Passed | Model calls | Mean input tokens | Mean reasoning tokens | Mean elapsed | Mean estimated upper-bound cost |
|---|---:|---:|---:|---:|---:|---:|
| DeepSeek-V4-Flash direct | 3/3 | 1 | 17,067 | 0 | 2,428 ms | $0.00011725 |
| DeepSeek-V4-Pro direct | 3/3 | 1 | 17,146 | 321 | 7,281 ms | $0.00047409 |
| isolated DeepSeek-V4-Flash extraction then DeepSeek-V4-Pro decision | 3/3 | 2 | 17,653 total | 167 | 6,773 ms | $0.00037050 |

The repeated trace is retained locally as
`2026-07-11T02-54-12.641Z-isolated-deepseek-model-handoff.json`.

Provider cache reads dominated the repeated run, so its cost column must not be
read as a general price ratio. The earlier cold one-trial diagnostic provides
a more informative uncached comparison:

| Profile | Uncached input tokens | Elapsed | Estimated upper-bound cost |
|---|---:|---:|---:|
| DeepSeek-V4-Flash direct | 17,067 | 3,032 ms | $0.00245630 |
| DeepSeek-V4-Pro direct | 17,146 | 5,956 ms | $0.00772995 |
| isolated handoff | 17,653 total | 8,130 ms | $0.00298434 |

On that cold path, the isolated handoff cost about 61% less than asking
DeepSeek-V4-Pro to read the full log, but took about 37% longer because it made
two serial requests. DeepSeek-V4-Flash direct remained both cheaper and faster,
and it was equally accurate on this fixture. The batch therefore does **not**
show that escalation to DeepSeek-V4-Pro was needed.

One earlier repeated attempt was interrupted by transient `ECONNRESET` and TLS
certificate verification failures after provider retries. It was excluded
from model results. The lab was then changed to retain structured partial
failures instead of losing the whole batch. The successful repeated run had
zero infrastructure failures.

## Interpretation

### Supported observations

1. Same-history model switching is unsafe to assume even when the local model
   SDK exposes a per-step override. Provider history protocols are part of the
   continuation boundary.
2. Independent calls joined by a small typed, source-bearing packet avoid that
   protocol conflict without requiring a second agent runtime.
3. A cheap model can reduce the context sent to an expensive model for the
   tested extraction task.
4. Splitting a call adds latency and an extraction-error boundary. The packet
   must therefore be inspectable and validated; model summaries are not new
   learning facts.
5. OpenCode's studied small-model uses are consistent with isolated auxiliary
   calls, not mid-turn brain replacement.

### Unsupported claims

This batch does not establish that:

- DeepSeek-V4-Pro should handle ordinary learning decisions;
- a router should infer model difficulty from every turn;
- extraction packets are sufficient for pedagogical explanations;
- a small model is reliable over arbitrary learner records;
- two model calls should be represented as two user-visible agents; or
- cost measured under provider caching transfers to production traffic.

## Reduction boundary after ALS-011

No custom multi-agent framework is justified by this experiment. If a future
task demonstrates that DeepSeek-V4-Flash is insufficient and DeepSeek-V4-Pro
adds value, the smallest reusable shape is:

```text
bounded source material
  -> independent DeepSeek-V4-Flash extraction
  -> validated evidence packet with source reference
  -> fresh DeepSeek-V4-Pro request
  -> ordinary executor authority
```

This is an optional call topology, not a learning-semantic primitive. The
learning layer still owns what counts as evidence, which actions are legal,
and what may become durable. Until a measured task needs escalation, the
single cheapest adequate model remains the simpler path.
