## Implemented boundary

The candidate adds one LearnerHome-owned `Assignment` authority without adding
a task manager, planner, scheduler, background process, or second Agent loop.
It owns generated Assignment/revision/effect identity, immutable complete
revisions, exact source-bearing correction, explicit lifecycle, current-only
supersession relations, typed command settlement, exact reads, and one bounded
Learning Context contribution. It does not own learning activity, adherence,
submission, grade, mastery, progress, capacity, allocation, or Tutor move
selection.

The implementation keeps these facts separate:

- immutable Assignment meaning and source/admission basis at commit;
- current Course/source/time projection at an exact consumer cut;
- explicit Assignment lifecycle versus elapsed time or silence;
- an independently valid Assignment versus any later Planning outcome; and
- obligation pressure versus the actual teaching move used to help the learner.

## Core authority and persistence

`packages/core/src/assignment.ts` and `packages/core/src/assignment/*` implement
the domain owner. A change set has one closed cause arm, one canonical payload,
one physical invocation, one semantic address, at most sixteen intents, and an
atomic terminal result. Learner reports, exact Artifact/Representation source
observations, and exact later root-model-operation corrections retain different
causal addresses. Physical replay and semantic duplicate/conflict resolution
are distinct: exact physical replay remains first, while every new physical
identity must pass the ordinary-interactive-root lineage check before semantic
address lookup. Semantic duplicate/conflict resolution then precedes live
source, permission, and head checks.

Committed truth is derived only from a sealed effect, exact revision set,
domain effect/receipt binding, and applied physical settlement. Current heads
are derived from immutable revision history. Direct correction can change any
legal disposition without manufacturing an intermediate `open` snapshot.
Current supersession validation sees the final batch, preserves historical
edges, rejects self/cycle/dangling/duplicate-current-incoming relations, and
does not write the target Assignment.

The V21 migration adds the Assignment tables and constraints to the single
`repa.db` lineage. It replaces only the generic terminal-validation trigger
whose V21 semantics must recognize Assignment semantic replay. It does not
rewrite Goal, FutureAttention, Session, Turn, or existing Learning Context
truth. Session deletion can remove transcript/Turn rows without deleting or
blocking the independent Assignment effect and receipt identity.

## Source, time, and historical-cut truth

Learner-occurrence, Artifact, and Representation reads retain owner-native
dependency tuples rather than one synthetic availability flag. Exact Assignment
revision reads never consult current external owner state. Current composite
reads bind `asOf`, the exact Assignment owner cut, scope relations, time-derived
due/expiry relations, and external owner dependencies.

The candidate adds narrow owner seams for persisted source-proof revalidation
and conservative historical reads. If a source owner changes outside an exact
old cut, the owner seam emits an internal `changed_after_as_of` sentinel and the
Assignment consumer returns typed stale truth without any later owner payload;
it never relabels current state as historical state. Clock passage performs no write. Named-IANA fold
resolution accepts only a matching explicit offset, while gaps, contradictory
offsets, and `-00:00` remain invalid.

The real file-backed Representation trace is:

```text
Representation available + ordinary current use eligible at Artifact R1
-> Artifact advances to R2
-> Representation remains available but current use is grant_required
-> learner authorizes continued use
-> Representation remains available and current use becomes eligible
```

Across the trace, the exact Assignment revision, revision reference, Assignment
owner cut, effect count, and revision count remain unchanged. An old `asOf`
reports only that later owner changes exist.

## Reads, Context, and ordinary Tutor use

Assignment current, exact revision, exact historical projection, history, and
discovery reads are typed, bounded, deterministic, and zero-write. Cursor
payloads bind query, owner cut, `asOf`, the next page's bounded exact dependency
set, and both dependency-set and whole-cursor fingerprints. Pagination
byte-fits a non-empty prefix and reports exact total/returned/omitted counts;
same-timestamp drift of an upcoming source invalidates the old cursor.

Learning Context policy/renderer/catalog version 4 contributes every current

## OpenCode command, permission, carrier, and recovery

`update_assignment` and `assignment_read` use the existing learning-command,
tool registry, permission, Session, Turn, and recovery substrate. The write is
ordinary-interactive-root-only; a delegated Agent may receive explicit read
authority but cannot make the write visible or admissible, including when it
tries to probe an already occupied semantic address. The permission projection
binds exact source basis, generated candidate identity, proposed complete
meaning—including a generated replacement successor's full snapshot—its
disposition/relation consequence, and the non-implications before approval.
The retained typed Tool carrier distinguishes committed, already-applied,
no-change, rejected, interrupted, and failed settlement.

Policy denial and exact prompt rejection settle durably with no Assignment
identity, revision, effect, or seal. Prompt abort settles `prompted_abort` with
the same zero-domain-write property. Restart reads durable physical/domain
truth and does not blindly redispatch semantic work. The read tool resumes a
cursor with the cursor-bound `asOf` instead of sampling a new wall clock for
page two.

## Decisive counterexamples closed by the candidate

- `completed -> cancelled` is one direct successor, not `open -> cancelled`.
- the maximum legal completed snapshot preserves exact completion replay;
  direct cancellation adds exactly one revision/effect/seal/receipt, and a
  one-byte-over snapshot creates no domain effect.
- a superseded Assignment can correct its payload while preserving its exact
  target, retarget, or clear the edge; historical edges remain exact.
- the same exact source locator with changed semantic payload conflicts rather
  than obtaining a new effect address.
- an all-no-change command seals its semantic address without creating an
  Assignment effect; exact later reuse is already applied and changed reuse,
  including a newly added create, conflicts.
- two candidates admitted before an identical source-address winner commits can
  both terminalize truthfully; the loser reuses the winning receipt and remains
  recoverable without new permission or redispatch.
- pure learner direction cannot create, rewrite, or replace source-bearing
  obligation truth; an exact owner-read correction-created successor retains the
  predecessor's effective source.
- an Artifact/Representation source cannot borrow the issuing learner
  occurrence's civil zone.
- an old Representation cursor becomes typed stale for later revision/grant,
  later Artifact ineligibility, and same-`asOf` upcoming-source drift without
  leaking later owner fields.
- Course withdrawal does not block correction that carries the existing exact
  scope, while adding a withdrawn Course remains invalid.
- all five provider-visible non-Assignment examples produce no Assignment tool
  call or durable row.
- malformed civil dates are rejected by both due and expiry database arms.
- a later root model operation under the same learner occurrence has its own
  exact correction address; identical replay, conflicting reuse, and head races
  remain distinct.
- a new delegated physical identity is rejected before it can observe an
  occupied Assignment semantic address or create terminal domain evidence.
- an admission-time all-no-change candidate cannot settle against A@1 after a
  concurrent legal correction makes A@2 current.
- two individually valid replacements cannot produce duplicate current incoming
  edges; the entire batch remains atomic.
- one maximum sixteen-intent batch jointly proves terminal correction, exact
  edge preserve/retarget/set/clear, generated and bound successors, maximum
  source/rationale fields, seventeen sealed revisions, exact historical edge
  retention, and exact physical replay.
- source deletion after an old cut does not rewrite that cut; a change effective
  within the cut makes the retained dependency stale.
- a maximum sole Assignment fits completely; two-to-one byte fit and nine open
  Assignments both remain multiple with exact omission and no promoted winner.
- elapsed due/expiry time changes only derived relation and never disposition,
  activity, completion, or learning.
- a valid Assignment survives transcript deletion, permission/presentation
  failure, absent Planning, and every external source projection change.
