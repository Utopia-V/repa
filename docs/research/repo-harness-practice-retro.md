## 有效的实践

**审查循环抓的是「事实-声明」偏差，不是风格。** 四个 PR 共 26 条 finding（据各 PR 评论记录），集中度依次为：事实错误（如把 `import type` 依赖写成值依赖）、自相矛盾的规则（文档声称的强制 > 脚本实际覆盖）、遗漏的机械可验规范、死链接；记录中无纯风格意见——外部模型在只读沙箱里逐行核对声明与代码，是单人自审无法替代的。

**文档作为校验规则来源，兑现了「一次性捕获、持续强制」。** `check-architecture.mjs` 直接解析 `ARCHITECTURE.md` 的模块边表，没有第二份真相；边表改动即校验改动。首次真实运行即据当时运行记录抓到一处真实漂移（用户未跟踪研究文档引用旧 ADR 文件名）。

**remediation 注入错误信息。** 校验违例输出「违例 + 可执行的修复指引」，由自测断言其文本。违例不再只是拦截，而是把修复方法注入到下一个 agent run 的上下文里——这是文章实践中性价比最高的一条。

**校验器自带 `--self-test`。** 共 14 个正反案例（12 架构 + 2 文档）在临时夹具里覆盖所列违例（逆向边、值导入仅 type 依赖、坏链接、缺小节、ADR 重号、超行数、TODO、动态导入绕过），并在代表性案例中断言违例与修复指引文本。校验器自身的行为因此是受测契约，不是口头承诺。

**执行计划作为一等工件稳定了多 PR 工作。** 蓝图的决策日志记录了 5 个范围决定（含用户确认），进度日志记录了每轮审查；两次提交事故由提交历史与巡检清单第 7 条留痕。跨 4 个 PR、多轮审查的工作没有丢失上下文。

## 待调整的实践

**「机械化」标签纪律。** 两个不同 PR 的审查都出现同一类病：文档声称的强制范围大于脚本实际覆盖（如「文档与代码同源」被整体标成机械化，实际脚本只管边表和链接）。这是系统性偏差：写文档时对工具能力的乐观估计。对策已落地——golden principles 的标签逐条与脚本能力对齐，审查 brief 里固定加入这一核对项。

**提交范围卫生。** 两次把未跟踪文件误扫进提交（均因目录级 `git add`），第一次在推送前恢复，第二次已推送后补移除（PR 净差异归零，历史暴露处置待用户裁定）。对策：巡检清单第 7 条（commit 前核对 `git show --stat`，禁止目录级 add）；机械强制候选（pre-push hook 或远端 CI 检查）列入后续增量。

**单模型审查面板。** kimi 未安装，全部轮次为 codex 单面板。文章实践强调多 agent 的偏差多样性；单面板下「面板共识」退化为「单模型意见」。装好 kimi 后恢复双面板。

**原始审查报告是易逝的。** 审计原文存于 `/tmp`（重启即失），持久的只有 PR 评论中的摘要。目前够用；若未来需要完整 backtrace，把浓缩报告归档进仓库或 issues。
