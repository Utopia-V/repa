# ALS-024 source-linked performance occurrence architecture-proof protocol

Date: 2026-07-13

Status: pre-registered documentation-only architecture proof. No executable lab,
production contract, schema, runtime change, harness work, or live-model run is
admitted by this record.

## Decision question

The current production path can preserve a source-linked Agenda reason, recover
it in a fresh Session, and ask for an independent learner response before Tutor
disclosure. Once a complete learner response serves that purpose, Agenda can
mark the concern addressed. The existing tests deliberately establish that this
creates no learner evidence.

That is correct for Agenda, but it leaves a concrete later-consumer question.
An independent correct response and an independent incorrect response both
serve the Agenda purpose and therefore have the same addressed disposition.
In a later fresh Session, however, the Tutor should not necessarily make the
same move. A response produced after decisive help must also remain distinct
from the same answer produced independently.

The question is:

> Does a later fresh-Session Tutor decision require one narrow, source-linked
> performance occurrence, or can the existing Interaction and Agenda
> authorities supply all required meaning through bounded projection and lazy
> reads?

Either answer can close the proof. A negative result is useful if Agenda plus
lazy Interaction detail distinguishes every required action without duplicating
meaning. A positive result admits only the minimum demonstrated occurrence
meaning; it does not admit a generic event, attempt, evidence, or mastery model.

## Why this is the current consumer

This proof extends the active teach, adapt, and return path at its first missing
downstream decision:

1. real material grounds a purpose-sensitive future return;
2. Agenda preserves the reason and the learner-response-before-disclosure
   constraint;
3. a fresh Session asks the intended independent question;
4. a learner response completes the intended occurrence;
5. Agenda records whether that future-attention purpose was served; and
6. a still later Tutor move needs to distinguish what happened during the
   response.

The first five boundaries exist. The sixth does not. Same-Session adaptation
can still use verbatim history and should remain zero-write when no later
consumer exists. The proof is current because it names a demonstrated
fresh-Session consumer, not because a Learner Record entity is next in an
entity-led roadmap.

The richer Course relation and corrected Assignment paths do not have this
property yet. Course already answers current route queries, while Assignment
still needs a representative cross-day workload proof. Neither is a reason to
delay or broaden this narrower distinguishability question.

## What “proof” means

This is a deterministic distinguishability, ownership, and failure-semantics
proof. It does not measure teaching quality or human learning.

The candidate passes only if:

- two histories that require different fresh-Session Tutor decisions collide
  under current durable context;
- the minimum candidate meaning separates those decisions;
- removing each retained meaning recreates a concrete false decision or an
  uncorrectable transition;
- the meaning remains bounded, source-linked, correctable, and lazily
  inspectable; and
- ordinary teaching and responses without this later consumer still create no
  learning record.

The phrase “source-linked performance occurrence” is protocol shorthand. It is
not a proposed TypeScript type, table, command, enum, or universal domain noun.
Fixture words such as “correct,” “incorrect,” and “assisted” are controlled
oracles for this proof, not admitted production categories.

## Accepted intent, working hypotheses, and unproved details

### Accepted intent

The following constraints are not under test:

- Interaction owns the durable Session and Turn transcript and preserves
  conversation context while it fits.
- A fresh Session receives bounded relevant context and retrieves cold detail
  lazily; it does not import every old transcript.
- Source and artifact authorities own material identity, revision, and
  provenance.
- Course View owns current route meaning; Agenda owns future-attention purpose,
  eligibility, and disposition.
- Reports, observations, evidence, inference, and resulting action are separate
  meanings. An observed answer does not establish ability or mastery.
- The program owns trusted identity, revision, permission, transaction,
  correction, and replay behavior. The Tutor may choose a later move within the
  legal context, and an exact current learner request retains priority.
- Ordinary explanation, demonstration, guided work, questions, and direct help
  do not require durable learning-state writes.
- There is no background daemon. Due and current meaning is derived when the
  application wakes.

### Working hypotheses

The proof tests these weaker claims:

1. Current Agenda disposition plus compact Course context cannot distinguish an
   independent correct response from an independent incorrect response after
   the original Session is absent.
2. The smallest sufficient additional meaning may be a source-linked occurrence
   that identifies the eliciting task, learner response, relevant assistance
   condition, and observed outcome without asserting mastery.
3. A fresh Session can consume a compact projection of that occurrence and read
   the exact question, response, assistance, or material only when the chosen
   move needs it.
4. When one completed response both establishes the candidate occurrence and
   changes Agenda disposition, those two semantic consequences require one
   atomic application or an explicitly truthful intermediate state.
5. A correction to assistance or outcome can change later context without
   deleting the original response or rewriting its source history.

### Deliberately unproved

This protocol does not assume that the candidate belongs in a particular table
or module, that outcome is stored rather than derived, that the Tutor should
schedule another review, or that any response supports a durable learner
inference.

## Authority checksum

| Meaning | Owning authority in the proof | Required separation |
| --- | --- | --- |
| Material bytes, locator, and observed revision | Source/artifact authority | A later Course revision cannot rewrite the historical source. |
| Current item and route position | Course View | Performance history cannot move the route by itself. |
| Agenda reason, operative learner-role constraint, eligibility, and disposition | Agenda | Addressed means the intended future attention occurred, not that the answer was correct or learning happened. |
| Exact Tutor question, Tutor disclosures, learner response, completion, and causal order | Interaction | Raw utterances remain transcript occurrences; another authority may reference but not silently restate them as truth. |
| Whether decisive assistance preceded the response | Initially an observation over Interaction sources | The raw Tutor message and the claim that it was decisive are different meanings and retain their provenance. |
| Whether the response met the controlled task criterion | A source-bearing performance observation, if the proof earns one | This is an observation about one response under stated conditions, not an ability inference. |
| Durable learner capability, confidence, or mastery | Learner Record inference, if a future consumer earns it | Absent from this proof and from every expected write. |
| The next explanation, feedback, application, or independent opportunity | Tutor composition and current model judgment within program constraints | The occurrence constrains a decision; it does not encode a hard-coded teaching action. |
| Learner override or correction | Interaction source plus the relevant owning domain transition | A learner correction changes the current projection with provenance; it does not erase history. |

The candidate, if earned, belongs conceptually at the Learner Record boundary
because it is a source-bearing observation consumed beyond one Session. That
statement does not choose its storage shape. Interaction remains the authority
for the raw response and assistance messages, and Agenda remains the authority
for its own disposition.

## Controlled three-case proof

All three cases use the same real Course View item, observed material revision,
source range, independent-prediction purpose, Tutor question, current route
position, and later learner input of “continue.” They run in isolated histories.
The correct-independent and assisted cases use the same answer text so response
content alone cannot explain the decision.

The task must have an inspectable criterion that can be evaluated
deterministically for the fixture. A model-authored grade is not an oracle.

| Case | Controlled history | Agenda consequence | Required later decision difference |
| --- | --- | --- | --- |
| Correct independent | The Tutor asks before disclosing the rule. The learner gives the criterion-satisfying response without decisive help. | Address the independent-response concern because its purpose occurred. | Do not repeat the same novice check merely because it was due before. Continue, deepen, compare, or apply as current context warrants; do not assert mastery. |
| Incorrect independent | The Tutor asks before disclosing the rule. The learner gives a criterion-failing response without decisive help. | Also address the original concern: the intended independent attempt happened. | Preserve the need for feedback, a changed representation, or another current learning move. Do not treat “addressed” as “correct,” and do not automatically schedule a revisit. |
| Assisted response | Before the learner response, the Tutor supplies the answer or a decisive rule. The learner then gives the same answer text as in the correct case. | Keep the independent-response concern open; guided completion did not serve that purpose. | Do not credit an independent check. When the concern is selected again, offer a genuinely answer-hidden opportunity or honor a newer exact request. |

The proof must preserve two distinct collision arguments:

1. **Outcome collision:** correct-independent and incorrect-independent have the
   same Agenda disposition but require different later moves.
2. **Condition collision:** correct-independent and assisted have the same
   answer text but differ in causal assistance and Agenda disposition. A later
   correction such as “I had already seen the answer” must reproduce that
   difference without altering the raw response.

Incorrect independent work must not keep the original concern open merely as a
proxy for “needs more learning.” If later future attention is useful, Agenda
receives a new source-linked reason through its own admission rule. Immediate
feedback needs no new Agenda concern.

## Minimum candidate meaning and ablation rule

The proof starts with meaning, not fields. A candidate may preserve only:

- the exact completed learner-response source;
- the eliciting Tutor-question source and Agenda purpose it served;
- the Course/material identity and historical revision needed to interpret the
  task;
- any relevant assistance observation with the Interaction sources that support
  it;
- the observed task outcome and its evaluator or learner-correction provenance;
  and
- correction/revision identity sufficient to derive one current projection.

It must not copy whole transcripts, infer mastery, classify a general task
family, rank future work, or contain a preselected next Tutor action.

Each meaning is retained only if its removal fails a controlled check:

| Ablation | Required counterexample |
| --- | --- |
| Remove outcome observation | Correct-independent and incorrect-independent collapse after Agenda is addressed. |
| Remove assistance basis | The same answer before versus after decisive disclosure cannot be corrected or audited truthfully. If exact lazy Interaction reads are sufficient, no duplicate durable assistance value is earned. |
| Remove eliciting question or purpose link | The same response text to materially different questions can be credited to the wrong purpose. |
| Remove material identity/revision | A response can be interpreted against changed or unrelated material. |
| Remove learner-response source | Retry, correction, and duplicate detection cannot name the causal occurrence. |
| Merge occurrence with Agenda disposition | Incorrect independent work falsely remains open, assisted work falsely closes, or “addressed” becomes an unsupported correctness claim. |

If the current authorities plus lazy reads pass an ablation, the candidate loses
that duplicated meaning. If they pass all cases, the result is “no new durable
occurrence,” and production remains unchanged.

## Same-Session and fresh-Session consumption

### Same Session

While the question, disclosures, and learner response remain in verbatim
context, the Tutor can adapt immediately from Interaction history. The proof
must show that no durable performance occurrence is required merely to produce
feedback in that Session.

The same-Session control therefore expects:

- correct, incorrect, and assisted histories to yield appropriate immediate
  adaptation from raw context;
- no new learner inference or mastery claim; and
- no candidate write unless the predeclared fresh-Session consumer exists.

### Fresh Session

The decisive condition starts another Session whose learner input is only
“continue.” The old transcript is excluded from initial model context.

The initial projection may include only the active Course neighborhood, relevant
Agenda state, and the minimum current performance summary earned by ablation.
Exact question, response, assistance, and material detail remain cold and are
read lazily when needed. The proof fails if it succeeds by importing the old
transcript or all learner history.

The trace must record:

- which compact meaning selected or constrained the later move;
- which exact source was read lazily;
- whether the current learner request overrode the historical candidate;
- why the move differs among the three cases; and
- that no unconsumed candidate fields were projected.

## Application, retry, stale input, crash, and atomicity

The raw learner response is an Interaction occurrence first. A failed learning
interpretation must not erase that admitted transcript. The narrower semantic
application, if earned, couples only the new performance observation and the
Agenda consequence that follows from the same complete response.

For the first proof, that application obeys these rules:

1. It names one complete Tutor question, one complete learner response, the
   governing concern revision, and the observed material revision.
2. It validates causal order and assistance sources at executor entry; model
   text cannot mint trusted identifiers or claim that no help occurred.
3. The performance consequence and Agenda disposition either commit together
   with one receipt or neither commits.
4. A physical retry with a new tool-call identity but the same semantic source
   returns the original result. A conflicting meaning for the same semantic
   source fails closed.
5. A genuinely new learner response is a new causal occurrence, not a retry of
   the earlier one.
6. No event bus, background recovery queue, or generic LearnerEvent abstraction
   is introduced to implement this boundary.

The required failure matrix is:

| Condition | Required behavior |
| --- | --- |
| Question or response incomplete | No performance consequence and no Agenda settlement. |
| State or concern revision stale before commit | Reject with zero semantic writes; recompile current context before retry. |
| Material origin changed | Preserve the historical binding, surface staleness, and never silently reinterpret against the new revision. |
| Exact historical source unavailable | Fail closed for any decision that requires it; compact labels are not substitutes for missing support. |
| Crash before semantic commit | Keep the raw Interaction occurrence; commit neither performance nor Agenda consequence. Agenda remains conservative until an explicit same-source retry. |
| Crash after commit but before receipt delivery | Replay returns the committed receipt and creates no duplicate. |
| Concurrent correction and settlement | One revision wins; the stale operation performs no partial cross-authority write. |
| Current learner request conflicts with historical default | Preserve the durable facts, honor the legal exact request, and leave unrelated Agenda state truthful. |

This protocol does not require automatic crash redispatch. The application can
reconcile explicitly on the next wake because the complete response source and
semantic identity remain durable.

## Correction and retry traces

Corrections append provenance and derive a new current projection. They do not
overwrite the original learner response, Tutor disclosure, or prior
observation.

At minimum, the proof must cover:

- **Assistance correction:** after a response was treated as independent, the
  learner reports “I saw the answer first.” The correction cites the report and
  original sources, changes the assistance observation, and atomically reopens
  the independent-response concern if it was addressed.
- **Outcome correction:** an evaluator or learner supplies inspectable support
  that the response was classified incorrectly. The current outcome projection
  changes while the original response stays fixed. Agenda remains addressed if
  an independent response still occurred.
- **Exact replay:** resubmitting either correction with the same semantic source
  returns the existing revision.
- **Conflicting replay:** a different correction under the same operation
  identity is rejected rather than last-write-wins.
- **New attempt:** another answer to a new question occurrence is admitted
  separately and never rewrites the first occurrence.

No correction creates mastery, route progress, or a new Agenda concern unless a
separate consumer and authority explicitly justify that consequence.

## Zero-write controls and counterexamples

The following must create no source-linked performance occurrence:

- an ordinary explanation, demonstration, analogy, or clarification;
- asking a review or prediction question before a learner response exists;
- a learner saying “I know this” or reporting confidence;
- topic overlap with an old Course item;
- an explanation-purpose Agenda return completed entirely by a Tutor
  occurrence;
- direct help on current real work;
- same-Session adaptation where no later consumer has been declared;
- time becoming due or overdue;
- navigation, route progression, or Course realignment; and
- a response whose source, completion, governing purpose, or relevant condition
  cannot be established.

The bounded assisted case may produce a source-linked guided occurrence only if
the fresh-Session consumer needs to know that the response happened under
assistance. It never counts as an independent response, and the ablation rule
must delete the durable guided record if Agenda plus lazy Interaction detail is
sufficient.

A correct independent response does not automatically:

- establish mastery or confidence;
- advance the Course route;
- schedule review;
- close unrelated Agenda concerns; or
- select the next teaching method.

An incorrect independent response does not automatically:

- prove a stable misconception;
- create a difficulty label;
- keep the completed independent-response concern open; or
- create a new revisit.

## Proof procedure

No provider or agent harness participates. The controlled histories, expected
decisions, and evaluators are deterministic and inspectable.

### Stage 0: freeze the consumer

Before any lab or production design:

1. select one real local Markdown Course item with a criterion-backed
   independent question;
2. freeze the three histories and their exact complete Interaction sources;
3. predeclare allowed later move families and explicit false moves;
4. identify the source detail each allowed move may need; and
5. freeze the current-state baseline that excludes any candidate performance
   occurrence.

The expected move family may be “give corrective feedback” or “offer a new
answer-hidden application.” Exact Tutor prose is not scored.

### Stage 1: establish the current-state collision

Compile a fresh-Session view for each history using only current production
meanings: Course View, Agenda disposition, and the legal bounded Interaction
sources available through lazy reads.

Record whether the correct and incorrect histories remain distinguishable
without importing transcript history. If current authorities already yield the
right decisions, stop with a negative result and do not invent a record.

### Stage 2: test the minimum candidate

Add only the candidate meanings listed above. Recompile the same fresh-Session
views, run the three deterministic decision oracles, then ablate one meaning at
a time. Retain nothing that does not change a required decision, correction, or
failure property.

An isolated executable fixture may later live under labs only if paper
inspection cannot settle a boundary. It must never be imported by production.
This document does not create that fixture.

### Stage 3: pressure lifecycle semantics

Run the failure matrix, exact replay, conflicting replay, new-attempt,
assistance-correction, outcome-correction, and stale-source cases. Inspect
authority-owned state after every rejected or interrupted operation.

### Stage 4: perform the dogfood trace

Before any production promotion, exercise one non-toy local Course item through
three primary Sessions plus one correction Session:

1. **Session A:** work from real material and create the bounded
   independent-response Agenda concern.
2. **Session B:** on a fresh “continue,” lazily recover the source, ask before
   disclosure, and admit exactly one of the three controlled response histories.
3. **Session C:** on another fresh “continue,” compile only bounded current
   meaning, lazily inspect exact history if needed, and choose the predeclared
   appropriate move family.
4. **Correction:** apply one assistance or outcome correction, start Session D,
   and confirm that the current projection and later move change while the
   original sources remain inspectable.

Repeat Sessions A–D in isolated histories for correct, incorrect, and assisted
conditions. The dogfood record must show context inputs, lazy reads, domain
revisions, receipts, Agenda disposition, and zero-write controls. It makes no
claim that a human learned, retained, or transferred anything.

The dogfood gate is an execution requirement for a later promotion decision,
not authorization in this documentation task to build a harness, call a live
model, or add production state.

## Entry gates

The proof may start only when:

- the parent decision is the fresh-Session action difference above, not “design
  a learner model”;
- one real source-grounded target and criterion-backed question are frozen;
- the correct, incorrect, and assisted histories differ only in the controlled
  response or assistance condition;
- every raw question, disclosure, and response source is complete and
  provenance-bearing;
- the baseline projection and exact lazy-read allowance are frozen;
- expected later move families and false moves are reviewable without model
  grading;
- the correction, stale, retry, crash, and zero-write oracles are frozen; and
- no unresolved conflict with ADR-0012, ADR-0013, or the Agenda contract
  remains.

If an entry gate fails, refine the consumer or fixture. Do not compensate with
a larger schema or a live-model sample.

## Exit gates

A result is complete only when it records all of the following:

- whether current Agenda plus lazy Interaction detail already suffices;
- the exact baseline collision, if one exists;
- correct-independent, incorrect-independent, and assisted later decisions
  with their Agenda dispositions;
- same-Session zero-write behavior and fresh-Session bounded consumption;
- one-at-a-time ablations showing why every retained meaning exists;
- source, response, assistance, observation, inference, and Agenda authority
  separation;
- correction, exact replay, conflicting replay, new attempt, stale source,
  interruption, crash, and atomicity outcomes;
- the full zero-write counterexample set;
- the real-material dogfood trace and correction trace; and
- an explicit statement that retention, transfer, understanding, and model
  policy reliability were not tested.

A positive result may admit a narrow production proposal only after these gates.
A negative result must say which existing authority supplies the later decision
and remove the candidate from the roadmap.

## Stop gates

Stop without promotion if:

- the only consumer is in the same Session;
- Agenda state plus bounded lazy Interaction reads already make every required
  later decision;
- the fixture needs a generic mastery score, task taxonomy, evidence ontology,
  scheduler, prerequisite graph, or multi-candidate ranking policy;
- a live model is required to manufacture the outcome oracle;
- the correct/incorrect criterion or assistance boundary cannot be inspected;
- success depends on importing the old transcript into fresh context;
- source identity or revision cannot be preserved;
- partial cross-authority commits cannot be made truthful;
- the candidate is useful only because it resembles ALS-015 or ALS-016's
  rejected general evidence schemas; or
- the proposed meaning has no consumer after one ablation.

No prompt tuning, additional model reviewer, enum rescue, or generalized event
layer is permitted after a stop gate.

## Non-goals

This protocol does not design or admit:

- LearnerEvent, universal Attempt, universal Evidence, mastery, confidence, or
  misconception ontologies;
- a criterion/rubric framework or general grader;
- task-family or competency taxonomies;
- spaced-repetition scheduling, FSRS, review queues, or automatic revisit
  creation;
- Course graph, prerequisite, lineage, or route-progress changes;
- Assignment workload, deadline, capacity, allocation, or replanning state;
- a pedagogy state machine, mode runtime, intervention registry, or hard-coded
  next action;
- a generic transaction coordinator, event bus, recovery daemon, or agent
  harness;
- provider comparison, prompt optimization, or live-model qualification; or
- any claim about learning, retention, transfer, or educational effectiveness.

## Deliberately undecided details

Even a positive result leaves these choices open:

- storage location, table shape, TypeScript names, command names, and indexes;
- whether outcome and assistance are stored observations, derived projections,
  or lazily recomputed from exact sources;
- the vocabulary, if any, for assistance strength or outcome;
- how an eliciting task receives stable identity;
- whether a deterministic checker, learner report, model observation, artifact
  inspection, or several sources may author an outcome in later consumers;
- whether any performance observation supports a separate learner inference;
- fresh-Session projection and compaction budgets;
- whether an assisted occurrence needs durable representation after its Agenda
  consequence is known;
- reconciliation across changed Course lineage or material revisions;
- cross-course reuse;
- policy for selecting or timing a later task; and
- any schema migration or compatibility behavior.

These details stay undecided until the proof earns their meanings and a
production proposal explains ownership, legal transitions, persistence,
recovery, and failure behavior.

## Result record

The completed record must end with four short statements:

1. **Claim:** the one fresh-Session decision boundary tested.
2. **Evidence:** the decisive collision, ablations, lifecycle checks, and
   dogfood trace.
3. **Decision:** no new occurrence, or the exact minimum meaning admitted for a
   production proposal.
4. **Remaining unknowns:** every educational, model-policy, scheduling,
   inference, and representation claim not tested.
