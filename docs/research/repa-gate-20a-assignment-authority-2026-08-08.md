## Opening decision and admitted invariant

Gate 20A admits one independently useful authority, `Assignment`:

> A source-relative substantial learning obligation may be given one stable
> LearnerHome identity and immutable, exact, correctable revisions so the
> ordinary Tutor can understand the learning pressure and a later Planning
> authority can consume the same exact meaning. The record preserves what is
> owed, why it matters to learning, its exact source basis, optional due/expiry
> terms, and explicit current disposition. Only an Assignment-owned command may
> change it. Clock passage, silence, an elapsed plan, Tutor prose, generic tool
> work, produced artifacts, or learning elsewhere cannot invent activity or a
> lifecycle transition, and completing the Assignment never proves learning.

The Assignment must earn a real teaching, guided-work, review, or Planning
consumer. A deadline alone does not make an administrative obligation part of
the Learning System. Conversely, an Assignment remains valid when no plan
exists or Planning is unknown, infeasible, denied, interrupted, or failed.

Decision ID `G20A-OPEN-001`. Revision owner: this contract until accepted;
after acceptance, owning product/architecture documents own challenged product
meaning and this contract owns Gate-local mechanics and evidence.

## Parent question and strongest counterexamples

The parent question is:

> What smallest durable, correctable meaning lets Repa retain one real
> learning-relevant obligation for later teaching and Planning without becoming
> a todo manager, homework-completion robot, external submission system, or
> metric optimizer?

The boundary must survive these counterexamples:

| Counterexample | Incorrect collapse | Required distinction |
| --- | --- | --- |
| “I want to understand operating systems before the exam” | every dated substantial Goal becomes Assignment | learner-owned intended outcome remains Goal; Planning can consume Goal directly |
| The Tutor says “try three examples now” | every useful practice task becomes Assignment | a current teaching/practice move remains Interaction meaning unless a different durable authority is earned |
| “Pay the course fee by Friday” | every deadline-bearing obligation enters Repa | no Assignment without a stated learning consumer or learning context |
| A syllabus revision says problem set 3 is due Friday | source bytes mechanically entail current external truth | exact bytes/revision plus fallible Agent interpretation and correction remain distinct |
| The learner reports “I submitted it” | learner report equals externally verified submission or learning | an explicit local `completed` disposition may be supported; external delivery/acceptance and learning remain unproven |
| An open Assignment becomes overdue while Repa is closed | time automatically creates failure, breach, cancellation, or zero progress | overdue is a query-time relation only; no revision or activity fact appears |
| Planning cannot find enough capacity | planning failure invalidates the Assignment | the obligation remains; Planning settles infeasible/unknown/failure separately |
| Two weekly problem sets have identical titles | text or content hash is identity | separate obligation occurrences may have distinct generated identities |
| A typo changes Friday to Monday in the same source obligation | every source revision creates another Assignment | explicit correction creates the next immutable revision of the same identity |
| A deliverable is replaced by a materially different one | all changes remain one identity forever | explicit replacement supersedes the old identity and names an exact successor |
| Revision N says `completed`, but the same exact obligation was actually cancelled | correction must manufacture `open` before the truthful terminal state | one source-bearing correction appends one direct `cancelled` successor; no transient outstanding pressure is invented |
| Superseded A still points to B, but A's due term or wording was wrong | correcting A requires restoring it and deleting the valid A-to-B relation | the successor revision corrects A while preserving the exact current supersession basis |
| A later root model operation detects its own already-settled Assignment interpretation error | every later operation inherits the old learner/source effect address | an explicit Agent-correction occurrence is addressed by the exact issuing root model operation and remains anchored to an exact current Assignment head |
| The source Session or file is later removed | cascading deletion erases the obligation | Assignment and minimal source truth survive; source availability becomes unavailable |
| Two or nine open Assignments fit the same fresh Session | display order or byte fitting silently selects the first visible row | the exact eligible count, zero/sole/multiple mode, deterministic non-priority order, and every omission remain bound to the cut |
| Source S is available when revision N commits and later becomes unavailable | resolving exact N changes with current source state, or current state is frozen forever | N retains immutable source/admission basis; each current read or Context cut binds source-owner status and dependency locators separately |
| “Due August 10” is normalized to 23:59:59.999 | every civil date is an instant | local-date meaning remains a date with zone/comparator provenance |
| A Course is withdrawn | Course state automatically cancels every Assignment | missing/withdrawn scope is exposed; Assignment changes only through its owner |
| Assignment revision N is corrected to N+1 after model operation M was admitted | current reads silently retarget M | the old Context cut and exact reference keep N; only a new cut sees N+1 |
| The learner stops using Repa but studies elsewhere | absence means no work or violation | no activity inference; later re-entry asks only what the next learning decision actually needs |

If the Gate cannot preserve these distinctions without a universal task table,
model-certified source entailment, completion score, background timer, or
Planning-owned obligation state, it must shrink or reopen.

Decision ID `G20A-COUNTEREXAMPLE-001`.

## Learning purpose and non-goals

Assignment is admitted for its downstream learning contribution, not because
status transitions are easy to count. Its first consumers are:

1. the ordinary Tutor's bounded Context and lazy owner read, so an explicit
   learner request can be taught or worked through using the exact obligation;
2. Gate 21's exact-revision Planning handoff, so deadline pressure and later
   learning allocation do not hide obligation identity; and
3. Gate 21A/22/23's later selection, inspection, and integrated behavior.

`completed` and `cancelled` exist only so closed or withdrawn pressure does not
mislead later teaching and Planning. Neither is a product KPI. A learner can
complete an Assignment without learning, learn deeply without completing it,
or continue learning after the obligation closes. Gate 20A records none of
those equations.

Gate 20A does not optimize assignment count, deadline compliance, capacity use,
grade, score, or submission. It does not authorize the Tutor to perform hidden
work on the learner's behalf. Explanation, demonstration, guided work,
independent attempts, review, and correction remain peer Tutor moves selected
by the ordinary Agent under the exact learner request and later policy.

Decision ID `G20A-PURPOSE-001`.

## Vocabulary and non-equivalences

- An **Assignment** is Repa's source-relative, correctable interpretation of one
  substantial learning obligation occurrence. It is not an assertion that an
  external institution agrees with the interpretation.
- **Substantial** means useful beyond the current request and relevant to a
  later teaching, guided-work, review, or Planning consumer. It is not a fixed
  minute, token, point, or item-count threshold.
- **Obligation summary** is bounded Agent-authored semantic content describing
  the work or result owed. It is not a transcript copy, task decomposition, or
  submission artifact.
- **Learning context** states why the obligation belongs in Repa—its subject,
  Course relation, skill/content pressure, or later learning use. It is not a
  mastery claim or a prescribed pedagogy.
- **Scope** is LearnerHome-wide or a bounded nonempty set of exact Course
  identities. It is not a directory, LearningSpace, View, material selector, or
  current task.
- A **revision source basis** records what warranted Repa's accepted
  interpretation at that immutable revision. It is distinct from permission,
  model confidence, external truth, and current source-owner availability.
- A **due term** is the source-stated temporal boundary, including unresolved or
  explicitly no deadline. Gate 21 separately decides whether and how it becomes
  an accepted planning input.
- **Disposition** is Assignment-owned outstanding/closed/replacement meaning.
  It is distinct from query-time due relation, activity, progress, learning,
  submission, grading, and Planning status.
- **Completed** means an explicit source-bearing local decision that Repa should
  no longer treat the obligation as outstanding because the stated obligation
  was completed. It does not prove submission, acceptance, grading, mastery, or
  educational value.
- **Submitted** is an external effect/report with connector-specific truth. It
  is not a Gate-20A disposition.

Fixed non-equivalences:

```text
Assignment != Goal
Assignment != FutureAttention
Assignment != current Tutor task or inherited todo
Assignment != Plan line or Planning demand
Assignment != learner commitment
Assignment != Tutor-proposed practice
Assignment != external submission/grade
Assignment completed != learner learned
Assignment overdue != learner failed or did no work
```

A learner self-promise without an independently reported/observed obligation
remains Goal or future consumer-earned commitment meaning. A bare Tutor proposal
remains a teaching move. Gate 20A has no `tutor_issued` source arm because tool
permission does not give the Tutor normative authority to impose obligations.

Decision ID `G20A-VOCABULARY-001`.

## Owned logical records and semantic snapshot

Exact SQL and TypeScript names remain implementation details. The physical
schema must nevertheless keep these meanings distinct and database-enforced.

1. **Assignment identity.** A LearnerHome-owned generated Assignment ID and
   trusted creation time. It contains no mutable current payload, priority,
   score, Course owner, workload, capacity, progress, plan, or submission.
2. **Assignment revision.** A generated revision ID, owning Assignment ID,
   positive lineage version, exact predecessor when noninitial, complete
   semantic snapshot, disposition, causal source/authorship facts, trusted
   commit time/order, and producing Assignment effect. Revisions are immutable.
3. **Scope membership.** Exactly one closed arm: LearnerHome-wide with no Course
   rows, or one to eight exact Course IDs. Exact Course currentness/withdrawal is
   read from the Course owner; Assignment does not copy it.
4. **Revision source basis.** Each revision stores immutable
   `effectiveSourceBasisAtCommit`, `sourceAdmissionBasisAtCommit`, exact mutation
   authorship, and whether the effective basis was carried from the predecessor
   or corrected with a new exact source. Admission-time availability may be
   retained as historical proof; current source availability is never a member
   of the immutable Assignment revision.
5. **Due and optional expiry terms.** Closed typed temporal arms preserve date
   versus instant meaning, comparator, normalized value, and trusted zone/tzdb
   facts. Query-time relations are derived and never stored as lifecycle.
6. **Supersession membership.** A `superseded` head names one distinct successor
   Assignment and exact successor-basis revision. Disposition and current
   supersession relation form one complete snapshot: `superseded` has exactly
   one target, every other disposition has none. Current-head graph validation
   rejects self-link, dangling target, duplicate current incoming edge, and
   current cycle; immutable historical links remain readable but do not consume
   current degree or participate in the current cycle check.
7. **Assignment change-set effect.** A generated domain effect ID, one exact
   tagged Assignment causal occurrence—learner report, source observation, or
   explicit Agent correction—one cause-specific fixed mutation slot, canonical
   payload fingerprint, a bounded ordered set of semantic intents with exact
   owner-resolved before/after snapshots, source/authorship facts, and
   deterministic results. One effect may commit several Assignment revisions
   without creating several replay addresses for the same causal occurrence.
8. **Learning-command receipt and physical settlement.** Gate 8 identities bind
   the exact Turn/Input, root Agent model operation, Tool Part, capability,
   permission, effect, terminal settlement, and durable acknowledgement.

Every revision stores a complete semantic snapshot:

```text
assignmentID
revisionID / version / predecessorRevisionID
obligationSummary
learningContext
scope
creationSourceBasis
effectiveSourceBasisAtCommit
sourceAdmissionBasisAtCommit
mutationAuthorshipBasis
sourceBasisRelationToPredecessor: carried | corrected_with_new_exact_source
dueBasis
optional expiryBoundary
disposition
optional exact supersession target and target-basis revision
```

No mutable current-source fact lives inside an immutable revision. Exact
revision resolution returns only the revision-local bases above. Current source,
Course, head, and clock relations are cut-bound derived projections with their
own owner-native dependencies.

The first contract fixes conservative domain-local bounds:

- obligation summary: 640 UTF-8 bytes;
- learning context: 384 UTF-8 bytes;
- exact learner/source excerpt retained by the revision source basis: 1,024 UTF-8
  bytes;
- Agent correction or lifecycle rationale: 1,024 UTF-8 bytes;
- Course scope: at most eight exact Course IDs; and
- one canonical automatic Assignment semantic entry: at most Gate 18's existing
  2,048 UTF-8-byte ceiling, measured after full canonical serialization.

No field is silently truncated. Source expressions, detailed history, long
source excerpts, and correction rationale remain lazy owner-read detail rather
than automatic Context payload. Contract-closing evidence must generate every
reachable maximum through real domain admission and prove a truthful automatic
entry under 2,048 bytes. If it cannot, this contract is falsified and must be
reopened with explicit revised bounds before implementation continues;
implementation may not silently shrink fields/counts or claim locator-only
degradation as acceptance.

There is no mutable `current_assignment` payload, universal Agenda item,
generic JSON fact bag, task checklist, content-hash identity, or model-authored
external ID. A commit seal or equivalent database-enforced construction prevents
a revision from becoming visible without its effect, receipt, and terminal
settlement.

Decision ID `G20A-RECORD-001`.

## Source, authorship, and epistemic boundary

The Assignment database is authoritative for Repa's accepted interpretation and
current disposition, not for independent external truth. The ordinary root
Agent is semantic author; the runtime proves structural facts only.

### Creation sources

Gate 20A admits exactly two creation arms:

| Source arm | Runtime-trusted binding | Durable, fallible meaning |
| --- | --- | --- |
| `interpreted_learner_report` | exact current root learner occurrence, bounded excerpt/range/hash, exact issuing root Agent model operation, source temporal context, capability, and permission | the learner reported an existing learning obligation and the Agent interpreted it as this Assignment; it is not independently verified external truth or a learner promise |
| `interpreted_source_observation` | exact admitted Artifact/Representation revision and bounded selector/locator or source observation, exact bytes-present fact where available, exact issuing root Agent model operation, capability, and permission | those exact source facts were available and the Agent interpreted them as specifying this learning obligation; presence does not prove source authority, current world truth, or semantic entailment |

Gate 20A does not admit `tutor_issued`, `model_proposed`, or
`learner_self_commitment`. A Tutor may recommend practice; that is not an
obligation. A learner may state a Goal or promise; that is not automatically an
Assignment. A later product decision may add an obligating issuer only after it
defines normative authority, learner override, correction, and truthful
presentation.

### Mutation sources

Every revision after creation carries exactly one Agent-authored mutation arm:

| Mutation arm | Runtime-trusted binding | Durable, fallible meaning |
| --- | --- | --- |
| `interpreted_learner_report` | exact current root learner occurrence plus bounded excerpt/range/hash and exact issuing root Agent operation | the Agent interpreted the learner as reporting corrected obligation/source facts or a lifecycle fact; the report is not external proof |
| `interpreted_learner_direction` | exact current root learner occurrence plus bounded excerpt/range/hash and exact issuing root Agent operation | the Agent interpreted the learner as directing how Repa should use its local Assignment record, especially dismissing or reactivating pressure; it does not claim an external source change |
| `interpreted_source_change` | exact newly admitted source revision/observation/locator and exact issuing root Agent operation | the Agent interpreted new exact source facts as correcting or closing the obligation; source presence is not semantic entailment |
| `agent_correction` | exact prior Assignment head owner read, exact issuing root Agent operation, capability/permission, and bounded correction rationale | the Agent corrects its own earlier fallible interpretation; it cannot fabricate a learner direction, external source event, activity, or submission |

Complete before/after snapshots and typed change intent distinguish changed,
carried, corrected, and no-change meaning without a universal field-provenance
framework. Unchanged fields retain recoverable predecessor provenance. A
revision uses exactly one closed source-basis action:

```text
preserve_predecessor_source
rebind_current_source_to_exact_learner_or_source_basis
```

`agent_correction` may preserve the predecessor's effective source while adding
the exact correcting model operation, owner read, and rationale. A new learner
report or source observation may rebind the effective source for the successor.
Neither action rewrites the predecessor or the immutable creation source.

Source arms constrain final truthful meaning rather than force a transition
path. `complete` and a real source-level `cancel` require an exact learner report
or exact source change. A direct correction of Repa's prior terminal,
outstanding, or supersession interpretation may use a report, source change, or
`agent_correction` when the retained exact basis is sufficient. `dismiss`
requires learner direction or correction of Repa's own mistaken local use.
`reopen` means the prior terminal fact was true and a later source-bearing event
made the same obligation outstanding again; correcting a terminal record that
was never true is a direct one-successor correction, not a reopen. Permission
alone supplies none of these bases.

All Assignment mutations in this Gate are root-Agent issued. Delegated Agents
may inspect bounded source material and return evidence to the root, but cannot
borrow a learner occurrence, constitute an obligation, or directly mutate
Assignment. A later source-scoped delegated write would require a separate
capability and authorship decision.

Permission proves authorization to attempt the command. It does not prove
learner assent, obligation truth, source authority, completion, or semantic
correctness. Presentation says “learner reported…”, “Agent interpreted this
source as…”, or “Agent corrected its earlier interpretation…” as appropriate.

`sourceAdmissionBasisAtCommit` records the exact owner proof used when the
revision was admitted, including availability-at-commit when applicable. It is
historical evidence, not a promise of later availability. A current source
projection belongs to the consuming read/Context/Planning cut and binds the
source owner's exact locator, owner-native version or tombstone/watermark, and
`asOf` time. Occurrence, Artifact, and Representation arms retain their native
state distinctions; in particular active Artifact-source availability and
exact Artifact-revision resolvability, and Representation availability and
ordinary-current-use eligibility, are separate facts rather than one boolean.

Source or Session deletion never cascades an independently useful Assignment,
revision, effect, receipt, or settlement. The bounded revision meaning and
source/admission basis remain byte-identical. A fresh composite read may report
the exact source-owner state as unavailable, missing, unbound, integrity-
mismatched, explicitly deleted, or another owner-native state; it never
reconstructs deleted bodies or changes the exact Assignment revision.

Decision ID `G20A-SOURCE-001`.

## Identity, correction, and replacement

One generated Assignment identity denotes one source-recognized learning
obligation occurrence. The ordinary Agent decides continuity using bounded
Assignment and source reads:

- due-date, wording, scope, or source-interpretation corrections may remain the
  same Assignment;
- an exact source revision does not automatically create a new identity;
- identical recurring problem-set wording may denote distinct identities;
- a changed deliverable may remain the same identity when the source treats it
  as a revision; and
- a materially distinct replacement is a new identity.

The runtime never decides continuity by title similarity, embedding, content
hash, file path, Course identity, time gap, deadline, or source revision alone.
When same-versus-new materially changes durable history or later Planning, the
Agent asks one learning-level clarification. The learner never supplies internal
IDs.

The linear revision invariant is:

- version 1 has no predecessor;
- every successor names the exact current head and commits
  `previousVersion + 1`;
- one head may be consumed only once;
- every revision is immutable and complete;
- the database rejects branches, skipped/reused versions, cross-Assignment
  predecessors, dangling relations, or unsealed effect/receipt construction;
  and
- current head is derived from history, not a second mutable semantic payload.

A correction never mutates revision N; it creates one complete N+1 directly at
the truthful final snapshot. Exact old reads, Context cuts, historical
supersession edges, and future Planning references keep N. No intermediate
revision may exist solely to make a correction reachable.

Correction under one identity means the source-recognized obligation occurrence
continues while its interpretation, scope, source, due/expiry term, disposition,
or supersession relation is corrected. The successor carries one closed relation
action:

```text
preserve
set_or_retarget { exactTargetAssignmentID, exactTargetRevisionID, version }
clear { explicitFinalNonSupersededDisposition }
```

`preserve` retains no edge for a non-superseded predecessor and the exact same
target basis for a superseded predecessor. `set_or_retarget` requires final
`superseded`; `clear` requires an explicit `open | completed | cancelled |
dismissed` result. Disposition `superseded` is equivalent to exactly one current
edge; every other disposition is equivalent to none. Payload correction never
implicitly clears or retargets an edge.

Replacement means a distinct obligation occurrence supersedes an open one. One-
old/one-new replacement atomically commits the old `superseded` revision, exact
successor relation, new successor identity/revision, effect, receipt, and
settlement. A true split/merge uses explicit separate operations without
pretending to be one equivalence; bounded replacement groups remain consumer-
earned. Current graph constraints are checked after all distinct-head intents in
the transaction have materialized, so an explicitly cleared incoming edge and a
new incoming edge are judged by final current truth rather than operation order.
Historical edges remain readable but do not occupy current degree or create a
current cycle.

Decision ID `G20A-IDENTITY-001`.

## Lifecycle and time model

Assignment revision/disposition, source/report facts, and query-time clock
relation are separate axes.

### Stored disposition

Every revision has exactly one closed disposition:

```text
open | completed | cancelled | dismissed | superseded
```

- `open`: Repa currently treats the source-relative obligation as outstanding.
- `completed`: an explicit source-bearing command records that the stated
  obligation was completed and should no longer pressure later teaching or
  Planning. It is not learning, mastery, activity evidence, submission,
  acceptance, grading, or product success.
- `cancelled`: an explicit source-bearing command records that the obligation is
  no longer owed. Learner refusal or silence is not cancellation unless the
  recorded source semantics actually support that meaning.
- `dismissed`: an explicit learner direction or Agent correction stops Repa
  from using the still-possibly-real obligation as current teaching/Planning
  pressure. It does not claim that the source cancelled it, that the learner
  completed it, or that the external obligation disappeared.
- `superseded`: a distinct exact Assignment identity replaced this obligation.

`withdrawn` is not another generic state. It may be a source-change rationale
supporting `cancelled`. Course withdrawal, source deletion, learner
disengagement, and Planning failure never cancel an Assignment automatically.

### Legal transitions

| Operation | Legal head | Result |
| --- | --- | --- |
| `create` | no existing identity | new identity revision 1, `open` |
| `revise` | any disposition | next complete revision with disposition and exact current supersession relation preserved |
| `correct` | any disposition | one direct complete successor with explicit final disposition and `preserve | set_or_retarget | clear`; previous interpretation is declared erroneous and no transient revision is created |
| `complete` | `open` | next revision `completed` |
| `cancel` | `open` | next revision `cancelled` |
| `dismiss` | `open` | next revision `dismissed`; source obligation truth is preserved |
| `reopen` | `completed | cancelled | dismissed` | next revision `open` only when the previous terminal meaning was true and a later source-bearing event made the same obligation outstanding again |
| `replace` | `open` | source becomes `superseded`; exact distinct successor is created or bound atomically |

Initial import of an already non-open historical Assignment is not admitted;
the first consumer needs current learning pressure, not an archival task system.
Updating content never implicitly changes disposition or a supersession edge.
Correcting `completed` to `cancelled`, a terminal state to `open`, or a terminal
state to `superseded` uses one `correct` effect and one successor; it never
passes through a knowingly false `open` head. A `completed -> open` correction
means the earlier completion interpretation was wrong, while `reopen` means it
was true and a later event made the obligation outstanding again; identical
final snapshots do not erase this causal distinction.

Correcting a superseded Assignment may preserve its exact target while changing
its own payload, retarget it to a different exact basis, or clear the relation
directly to an explicit non-superseded final disposition. “Restore” is the
`correct + clear` case; it is not an implicit transition to `open`. The former
target Assignment is never edited, cancelled, restored, or otherwise changed by
correcting the source Assignment.

Starting work, reading, explaining, producing an artifact, allocating time,
external learning, silence, time passage, or model narration never changes
disposition. `dismiss` requires an explicit learner direction or correction of
Repa's own mistaken admission; it is never inferred from disengagement. A
future application composer may combine an independently valid
activity/connector fact with Assignment completion only after it owns both
source meanings and an all-or-none consequence.

### Due and expiry terms

The Assignment owns the source-stated term. Gate 21 later owns whether and how
it becomes an accepted Planning input.

The closed due basis is:

```text
unresolved
explicitly_no_deadline
local_date { civilDate, comparator, zoneBasis }
instant { normalizedInstant, comparator, zoneBasis }
```

`unresolved` means no accepted term is known; it is not proof that none exists.
`explicitly_no_deadline` requires a source/report that states no deadline.
`local_date` remains a civil date and uses `inclusive | exclusive` boundary
meaning without inventing end-of-day. `instant` stores one normalized instant,
comparator, and exact zone-resolution provenance.

An optional separate expiry/acceptance-end boundary uses the same date/instant
and comparator semantics. Absence means no expiry fact is recorded. Deadline
never implies expiry.

Reads derive temporal relations from the stored revision and trusted clock:

- local date preserves `before | on | after` in the bound zone;
- instant preserves `before | at | after`, interpreted with the stored
  inclusive/exclusive comparator;
- `overdue` follows only from the accepted due boundary;
- `expired` follows only from an explicit expiry boundary; and
- an open Assignment may be overdue or expired without being completed,
  cancelled, failed, breached, or abandoned.

No clock read writes a revision, effect, receipt, activity, or frontier. A due
correction creates a successor revision. An old Context cut retains its old
revision, trusted clock, and derived relation.

### Civil-time computation

Gate 20A reuses the domain-neutral tagged Goal/FutureAttention calculation:

- named IANA zone plus pinned tzdb release;
- fixed offset;
- trusted causal `source` zone only when actually captured;
- exact `Z`/offset source spelling must equal the normalized instant and
  effective offset;
- `-00:00` is unknown rather than fixed UTC;
- naive local datetime is admitted only when a bound IANA zone resolves
  uniquely;
- DST gaps/folds fail unless explicitly disambiguated;
- host defaults and future tzdb changes never reinterpret an old revision; and
- date-only meaning remains date-only.

Source material without a trusted zone must supply an explicit named zone/fixed
offset or remain unresolved. Assignment owns the stored term; the shared civil-
time module owns only calculation.

Decision IDs `G20A-LIFECYCLE-001` and `G20A-TIME-001`.

## Command, effect, permission, and settlement

Gate 20A adds one capability-scoped typed Assignment mutation union and one
non-mutating Assignment owner read. Logical tool/module names are implementation
details; their semantic ownership is not.

Every mutation is issued by the ordinary interactive root Agent against exact
runtime-bound facts. Restricted Agents remain default-deny. A consequential
permission proposal exposes the exact operation, Assignment identity/head when
present, source arm, scope, due/expiry change, disposition consequence, and
replacement target before approval. Settlement exposes exact
`applied | already_applied | no_change | denied | conflict | failed` truth.

The command route reuses ADR-0009's distinct identities:

1. tagged Assignment causal occurrence;
2. root learner/source and Agent-operation provenance;
3. physical tool invocation; and
4. semantic Assignment effect.

The closed causal/address union is:

```text
learner_report {
  occurrenceID
} -> (learner_report, occurrenceID, assignment_change_set)

source_observation {
  sourceRevisionID
  locatorDigest
} -> (source_observation, sourceRevisionID, locatorDigest,
       assignment_source_change_set)

agent_correction {
  modelOperationID
} -> (agent_correction, modelOperationID,
       assignment_correction_change_set)
```

`modelOperationID` is the runtime-admitted ordinary interactive root Agent
logical operation—the persisted Assistant Message identity in the current Turn
substrate. Its exact Turn/Input/root learner-occurrence lineage remains
provenance but the root learner occurrence is not the correction address. A
different later model operation does not automatically earn this arm: the
change set must explicitly be `agent_correction`, every ordinary target must
bind an exact existing Assignment head, and standalone create is forbidden. An
anchored replacement may create/bind its one exact successor only because the
consumed head and relation give it a closed identity. Discovering a wholly
omitted, unanchored Assignment from old material requires a new admitted learner
or source occurrence, or a future separately proven create-address contract.

One change set carries one to sixteen ordered typed intents. Every update intent
binds exact Assignment identity, expected head, and named transition. A create
intent receives its generated identity inside the owner transaction. `replace`
may create/bind its one exact successor because the relation would otherwise
dangle. Duplicate target/head consumption, duplicate create ordinal, ambiguous
ordering, and over-count fail the whole change set rather than expose partial
Assignment truth.

One change set has exactly one cause class and cannot mix learner, source, and
Agent-correction addresses. `expectedHead` plus its Assignment-owner read/cut
reference is part of the canonical semantic payload, provenance, and final CAS
precondition; it is not part of the semantic address. Changing an expected head,
rationale, final snapshot, relation action, or intent set under an occupied
address is conflicting reuse, not a new cause.

Settlement order is:

1. exact terminal physical replay returns the stored physical result without a
   domain read; conflicting reuse of one physical identity is a physical
   conflict;
2. a new physical invocation validates the trusted Session/Turn/Input/root
   lineage, exact issuing model operation, sealed Tool candidate, and immutable
   envelope, then derives the tagged Assignment cause/address;
3. existing semantic address plus identical canonical payload returns
   `already_applied`, while the same address plus changed payload returns
   `conflict`; both settle before live source, expected-head, permission, or
   transition checks and never replace the first effect's provenance;
4. a free address validates its single cause class, root-only issuer, exact
   source relationship, owner-read/head, capability, permission, legal final
   transition, relation action, change-set bounds, and no-standalone-create rule;
5. a semantically empty free command returns `no_change` and writes no
   Assignment revision/relation/effect, while retaining its physical terminal
   settlement; and
6. final owner transaction rechecks the semantic-address race, source proof,
   exact heads, final graph, and transitions, then commits every Assignment
   revision/relation, the one effect, receipt, Tool Part settlement, exact
   model-visible results, and durable acknowledgement together or not at all.

Later Assistant/model operations under the same current learner report inherit
the same learner-occurrence change-set address. Reissuing the exact canonical
payload is `already_applied`; adding, removing, or rebinding an intent conflicts
and requires a genuinely new command-valid causal occurrence. An exact source-
observation locator has the same rule. A later exact root model operation may
instead use the explicit `agent_correction` address only after reading the
committed exact head and proposing a source-preserving correction; it cannot
reuse that model-operation address for an unanchored create. This prevents
resampling or post-tool continuation from minting another create ordinal while
allowing same-Turn/post-settlement repair of the Agent's own interpretation.

An exact new learner occurrence does not automatically authorize a duplicate
Assignment. The root Agent performs bounded owner/source reads and decides
`no_change | revise | replace | create`. The runtime does not use fuzzy
similarity, title uniqueness, hash identity, or Course/date keys as semantic
deduplication.

A natural request or exact source locator naming several Assignments uses one
bounded Assignment change set. Independent exact source locators or genuinely
new learner occurrences settle as independent later change sets; if one earlier
set commits and a later set is interrupted, the earlier truth remains and
re-entry never rolls it back or blindly resumes. Assignment plus Planning,
activity, Artifact work, or external submission is staged by default. A valid
Assignment must survive unknown/infeasible/failed Planning.

Decision ID `G20A-COMMAND-001`.

## Failure, deletion, interruption, and recovery

The existing Turn/Session/learning-command lifecycle owns cancellation and
restart. Gate 20A adds no scheduler, worker, retry daemon, or Assignment runner.

Required behavior:

| Condition | Required truth |
| --- | --- |
| interruption before local commit | no Assignment effect or partial revision |
| commit succeeds, later provider/TUI presentation fails | Assignment and settlement remain committed; no prose is required to make them true |
| exact physical retry | return stored settlement without another revision |
| same-source later Assistant reissues the learner/source claim | inherit the fixed learner/source address; return exact already-applied or conflict truth before stale-head rejection |
| explicit same-Turn/post-settlement `agent_correction` | use the exact later root model-operation correction address, bind the exact committed head, and append at most one direct truthful successor; no new learner message or transient lifecycle state |
| concurrent writes against one head | one successor wins; the other sees current stale/conflict references |
| direct terminal or supersession correction | one effect creates one successor/final current graph; original settlement, old revision, and historical edge remain exact |
| crash during local command | domain effect/revision/receipt/Tool settlement all commit or none; startup recovers settled identity |
| restart after ambiguous model work | never re-run the interpretation; a new command-valid admitted occurrence re-reads current state |
| source disappears during validation | a new-source arm revalidates its exact owner proof in the final transaction or commits nothing; a source-preserving Agent correction may rely only on the immutable admitted basis already retained by the exact head and must not infer deleted bytes |
| Session/source deletion after commit | preserve exact Assignment/source-at-commit basis; fresh composite reads bind the new owner-native source status without reconstructing removed bodies or changing old cuts |
| Course scope becomes withdrawn/missing | expose scope unavailability; perform no Assignment lifecycle transition |
| clock advances while Repa is closed | derive a new due relation on a fresh read; create no revision, activity, completion, or failure |
| Planning is infeasible/unknown/fails | preserve Assignment unchanged; Planning settles separately |

Gate 20A has no hard-delete command. Explicit correction/lifecycle preserves
history. Selective deep deletion remains post-baseline Data Lifecycle work with
its own cross-authority impact preview and authorization.

Decision ID `G20A-RECOVERY-001`.

## Owner reads and exact historical truth

The Assignment owner exposes bounded typed queries for:

- discover current Assignment heads by LearnerHome, exact Course scope, and
  disposition against one Assignment-owner cut;
- get current head by Assignment ID;
- get exact immutable revision by Assignment/revision identity;
- bounded immutable history and predecessor/successor traversal; and
- a separate current composite projection that derives head, scope, time, and
  source-owner relations against exact dependencies and trusted `asOf`.

Exact revision resolution returns only Assignment-owned immutable meaning:
obligation summary, learning context, scope, source/admission/authorship bases at
commit, due/expiry basis, disposition, and exact supersession relation/basis. It
does not return current source availability, current Artifact binding,
Representation ordinary-use eligibility, Course currentness, clock relation,
current Assignment head relation, or Planning state. Source deletion alone does
not make an `AssignmentRevisionRef` unavailable or create a new Assignment
revision.

The current composite projection is equivalent to:

```text
AssignmentProjectionAtCut {
  assignmentRevisionRef
  assignmentOwnerCut
  asOf
  currentHeadRelation
  dueExpiryRelationAtCut
  scopeCurrentRelationsAtCut[]
  sourceStatusAtCut {
    sourceOwner
    exactSourceLocator
    ownerRecordedState
    exactOwnerDependencyTupleOrWatermark
    asOf
  }
}
```

The source-status union remains owner-native. Occurrence availability binds its
exact occurrence/tombstone dependency. Artifact status separately exposes
active-source availability and exact cited-revision resolvability. Representation
status separately exposes `available | externally_missing | integrity_mismatch |
explicitly_deleted`, its availability version, Artifact dependency, and any
ordinary-current-use/grant relation. The projection reports owner-recorded state
at the cut; byte-reading tools still perform current admission/revalidation.

Every list/page reports:

- immutable Assignment-owner cut/watermark and trusted `asOf` time;
- exact `countAtCut`, returned count, cursor, truncation, and omitted count;
- deterministic order explicitly labelled non-priority;
- Assignment ID, exact head revision/version, disposition, obligation summary,
  learning context, scope, due/expiry basis and current relation;
- immutable source basis plus, only on a composite projection, exact
  source-owner status/dependency at that cut; and
- exact supersession relation when present.

A composite cursor binds the Assignment cut, ordered source dependency set,
dependency-set fingerprint, and `asOf`. Pagination either reuses a provably
frozen composite cut or returns typed stale-cursor truth; it never joins a later
source epoch to an earlier Assignment page. Assignment-owned eligibility/count
does not filter on source status, so omitted candidates need no fabricated
external-source dependency merely to be counted.

Discovery order is a stable audit/pagination order, not due priority, Tutor
selection, or Planning rank. Reads do not mutate, infer activity/completion,
retrieve deleted bodies, retarget old revisions, or make the first displayed
Assignment current. Historical audit is separate from ordinary current-use
projection.

Decision ID `G20A-READ-001`.

## Learning Context and ordinary Tutor consumer

Gate 20A extends Gate 18 with Context policy/renderer/capability version 4, a
versioned `assignment` owner/kind, and a lazy Assignment read capability. Older
cuts retain their original bytes and schemas. It reuses the exact request/
context-cut seam and ordinary released-v1 Agent loop; there is no second Tutor or
Assignment runtime.

When automatic Assignment context is authorized, the section always exists and
uses this closed producer scope:

```text
eligible := every exact current Assignment head in this LearnerHome
            whose disposition is open
```

Course default/current/withdrawn state, due/overdue/expiry, source availability,
Planning state, request keywords, embeddings, and model or host ranking neither
add nor remove eligibility. Assignment admission already established a learning
consumer; this section exposes bounded candidate pressure without choosing the
Tutor move. When the capability is withheld, coverage is `not_authorized`,
count/omission are unknown, entries are empty, and no identity or source fact is
leaked.

The section binds:

- exact Assignment-owner cut, trusted `asOf`, and exact pre-truncation
  `countAtCut`;
- mode `none | sole_candidate_pressure | multiple_candidate_pressure`, derived
  only from `countAtCut`;
- deterministic Assignment identity creation order then Assignment ID, labelled
  audit/pagination order and never priority;
- at most `MAX_ASSIGNMENT_CONTEXT_ENTRIES = 8` current-head entries;
- separate omission counts/reasons for `candidate_limit` and
  `gate18_byte_budget`; and
- for every retained entry, exact Assignment/head reference, bounded complete
  obligation summary and learning context when semantic value is retained,
  immutable source basis at commit, source status/dependency at this cut, scope,
  due/expiry basis and clock relation, exact supersession relation when present,
  and lazy-read availability.

`countAtCut` is computed before the eight-entry limit and byte fitting. Candidate
limit omission is `max(0, countAtCut - 8)`; byte-budget omission counts entries
removed by deterministic whole-cut fitting after that limit. A retained
locator-only entry records its semantic-detail omission in its own coverage
state and is not counted as a removed entry. If nine open Assignments yield
eight candidates and fitting removes three, the section
reports exact count nine and omissions `{candidate_limit: 1,
gate18_byte_budget: 3}`. If fitting leaves one visible row from an original count
greater than one, the mode remains `multiple_candidate_pressure`; visibility
never promotes that row.

Mode meanings are closed:

- `none`: this cut has no current open Assignment pressure;
- `sole_candidate_pressure`: the one complete candidate is available, but it is
  not a default/current Tutor move, priority, plan, commitment, activity,
  progress, or learning result; and
- `multiple_candidate_pressure`: exact total and omission truth remain visible;
  the ordinary Agent may honor an exact request, lazy-read within the authorized
  universe, make a transparent reversible local learning choice, or ask one
  learning-level clarification when materially necessary, but no row is a
  deterministic winner.

Every schema-valid complete Assignment automatic semantic value is at most
2,048 canonical UTF-8 bytes. With `countAtCut == 1`, its full semantic value is
mandatory and cannot become locator-only or be removed. With more than one,
section header, exact count/mode, non-priority order, omission, and lazy-read
coverage are mandatory; individual optional semantic detail may be reduced to
complete-field locator-only form or removed in deterministic order, with exact
byte-budget omission. No string is substring-truncated. If independently
mandatory sections still cannot coexist inside Gate 18's 32-KiB canonical and
16-KiB rendered limits, admission fails before provider open with typed fit
truth; it writes no partial cut or Assignment and does not resample, silently
shrink bounds, or rebuild the envelope on provider overflow.

Completed/cancelled/dismissed/superseded history remains lazy-readable unless the
exact request or current correction needs it. An exact current learner request
may focus the interaction without changing Assignment state. The cut records
Assignment-owner and retained-entry source-owner dependencies separately. A
source change after cut C0 leaves C0 bytes and transport retries unchanged;
current lazy byte access may return later-unavailable truth, while a fresh C1
binds the new source status. Rendering, composition, and lazy read perform zero
Assignment writes.

Gate 20A's learning-purpose trace is narrow and does not usurp Gate 21A:

```text
exact learner report or exact source observation
-> root Agent commits one Assignment revision
-> a fresh Session receives its exact learning context
-> an explicit request such as “help me understand/work through this assignment”
   can lazy-read the exact revision and enter the ordinary explanation,
   demonstration, or guided-work path
-> no completion, activity, progress, plan, or commitment is invented
```

Deterministic request/prompt/tool traces must prove the exact state-to-request
join and zero-write teaching path. Gate 20A does not claim general move quality,
cross-pressure arbitration, educational efficacy, or that Context visibility
alone selected a move. Those remain Gate 21A/23.

Decision ID `G20A-CONTEXT-001`.

## Exact Planning handoff and staged composition

Gate 20A exports an exact typed meaning equivalent to:

```text
AssignmentRevisionRef {
  assignmentID
  revisionID
  version
}
```

Resolving the reference yields only the exact revision's obligation summary,
learning context, scope, immutable effective/admission/authorship source bases
at commit, due/expiry terms, disposition, and exact supersession relation/basis.
It does not yield current source availability, Course currentness, current-head
relation, query-time due relation, workload estimate, remaining work, capacity,
progress, allocation, priority, plan status, adherence, or commitment.

If Planning admission needs current source-owner status, it binds a separate
source dependency projection with its exact owner-native locator/version/
watermark and `asOf`. Source deletion or drift alone does not make the
Assignment revision unavailable, advance its head, or change an already
accepted Planning input. Planning may separately derive that one of its own
source dependencies changed.

The decisive handoff oracle is:

1. bind Assignment revision N;
2. correct the Assignment to N+1;
3. exact N remains readable and unchanged;
4. fresh-current read returns N+1; and
5. no Context or future consumer pointer silently retargets N to N+1.

The oracle also covers a source status change with no Assignment correction:
exact N and its producer-currentness remain unchanged when N is still the head;
old cut C0 retains its source status at C0, a fresh C1 may bind a new owner-
native status, and neither read renames that change `producer unavailable`.
For a superseded revision, exact resolution includes its exact target basis but
does not instruct Planning to follow, replace, remove, or zero that producer.

Gate 21 owns whether a plan referencing N is current/stale, how due meaning is
accepted as a planning input, what capacity/workload facts apply, and whether a
successor plan is computed. Planning may never mutate Assignment.

Default composition is staged:

```text
Assignment commits or fails under Assignment rules
-> Planning reads the exact committed revision
-> Planning commits feasible / infeasible / qualified-unknown truth or fails
   without erasing the Assignment
```

No demonstrated learner invariant requires atomic create-Assignment-and-plan.
An explicit future application composer may add one only if each consequence is
invalid without the other.

Decision ID `G20A-HANDOFF-001`.
