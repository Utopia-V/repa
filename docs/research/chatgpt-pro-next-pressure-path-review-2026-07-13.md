# ChatGPT Pro review: next product-pressure path

Date: 2026-07-13

Status: Independent architecture review input. It informs Proposal 0006 but is
not an accepted decision or a substitute for repository evidence.

## Decision under review

After the first conditional Agenda purpose reached production, the next work
could plausibly have followed one of three directions:

1. admit a narrow learner-performance occurrence only if it changes a later
   Tutor move;
2. pressure the system with a real assignment, deadline, current time budget,
   due revisit, and direct-help override; or
3. expand Course representation into a more general graph.

The local phase-boundary audit had already rejected the third direction as a
predecessor. Course View is a versioned ordered hierarchy, Material Map and
Agenda are separate overlays, and no current consumer needs another relation.
The unresolved choice was therefore between learner-performance admission and
real-work constraints.

## Consultation identity and limits

The private ChatGPT Pro bridge ran the default live Pro selection reported as:

- model: `GPT-5.6 Pro`;
- thinking effort: `extended`;
- elapsed time: 23.1 seconds; and
- web search: not requested or used.

The prompt supplied the accepted product/architecture constraints, current
production evidence, the failed generic evidence experiments, the earlier B2
deadline trace, and the two competing next-step proposals. It asked only for
contradictions, failure traces, sequencing, local-gradient risk, and
expensive-to-reverse boundaries. The review did not receive repository access,
edit files, choose product values, or supply new source facts.

## Useful challenges

The review identified four consequences that survive local verification:

1. B2 proved a behavior, not production ownership. The dangerous questions
   are the local identity of an assignment, source and correction authority,
   deadline validity, and current-request precedence.
2. A narrow evidence experiment could still prove only that more context
   changes generated prose. Without a named future consumer and correction
   boundary, it risks recreating the rejected generic evidence direction.
3. The real-work path can also fail by silently growing priority scores,
   learning-value fields, a scheduler, and a generic task manager. Its first
   artifact must therefore be a semantic contract, not tables or a planner.
4. The expensive boundary is ownership, not storage layout: an external
   obligation, the learner's report of it, Repa's interpreted local record, and
   a one-Turn plan must not become one fact.

These challenges agree with local evidence. In particular, B2's historical
lab incorrectly attached an unrelated general-education report to the active
JavaScript course. That is a direct counterexample to copying its schema.

## What is adopted

- Choose the real-work conflict as the next pressure path.
- Write a behavior and semantic contract before production schema.
- Keep one-off planning in Session history.
- Admit no general evidence layer, scheduler score, task graph, or persistent
  plan.
- Make source, correction, temporal derivation, current-request override, and
  failure behavior explicit before implementation.

## What is not adopted

The review suggested that real work might later become an admission test for
learner evidence. That is possible but not established. Completing an
assignment, receiving help, and demonstrating learning remain separate
meanings. Proposal 0006 neither adds learner evidence nor makes the assignment
path a hidden evidence prerequisite.

The review also used the phrase “learner-owned commitment.” The narrower local
meaning is different: Agenda owns Repa's durable representation of a reported
real-work obligation. The learner may not own the external deadline, and Repa
does not become the authority for an institution's assignment system merely
because it stores the learner's report.

## Decision consequence

Proceed with a reviewable deadline-sensitive real-work contract. Reuse B2 as a
behavior oracle, not a production data model. A new provider experiment is not
a predecessor; deterministic ownership and failure checks come first, followed
by at most a bounded production smoke if the contract survives review.

Two subsequent read-only contract audits attacked product drift and state
integrity. Their findings changed the draft before admission:

- `completed` now means the tracked obligation needs no further action;
- deadline-first truncation is an explicit retrieval policy with paged active
  and recent-terminal inspection;
- every transition has command-specific semantic replay identity;
- reopen may atomically carry a corrected deadline;
- a new learner Input does not automatically authorize a duplicate entity;
- minute-precision civil time, IANA/offset provenance, normalization, and
  ambiguity are explicit;
- learning-related admission is named as correctable model interpretation, not
  a deterministic keyword rule; and
- post-settlement failure, global watermark scope, cold source paging, the
  no-Course runtime seam, and learner-visible inspection are covered.

Both audits re-read the amended contract and reported no remaining
production-admission blocker. This establishes design readiness, not runtime
correctness; implementation and verification remain separate evidence.
