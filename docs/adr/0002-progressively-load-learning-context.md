# 追加学习语境的当前视图

本记录约定目标设计；当前实现范围与运行方式见 [README](../../README.md#运行现有-tui)。

## 持久表示与读取

每个学习空间关联一份可编辑学习语境。简单空间可以直接关联一份文档，需要组合多份内容时，以小的结构化清单保存成员引用、顺序和必要分组，正文继续属于各自的文档。学习语境拥有自身的表示、组织及视图生成语义，按需要复用[共同的内容操作](0003-share-file-based-content-operations.md)；用户和 Agent 能够编辑与重组实际持久内容。学习语境视图是按这些规则生成、供模型使用的内容表示；前端预览组件可以读取同一结果，生成规则继续由语境模块持有。内部适配层消费生成的视图，不依赖一个固定语境文件。

组成成员支持展开与引用两种方式。展开将所选文档的当前正文或明确选择的模型可读表示放入语境视图，引用提供标题、内容引用和可选说明，供 Agent 按当前任务继续读取。多文件及其他格式的内容按显式选择的成员或相应能力提供的确定表示展开，其来源与所用修订随视图保留。普通文档链接保留为引用，视图生成只展开明确选择的内容，不沿普通链接或资源依赖递归读取整个空间。改变成员的使用方式不复制正文，移除成员只改变组成关系。前端可以展示按当前内容生成的语境视图并标明来源。

语境组装通过共同内容模块取得所需组成、正文与修订，对经 Repa 协调的变更，在完整提交边界观察需要共同读取的内容。发现外部变化且无法确认所用输入，或读取失败时，按准备错误处理，避免将部分更新拼接成一次完整语境。

## 请求与快照

每次请求准备时，Repa 从空间取得当前语境视图。稳定的产品指令和工具定义保持稳定；语境更新通过 Pi 的自定义消息机制追加到会话后段，不回写此前的输入前缀。消息保存一次完整视图，带有足以解释来源与所用修订的信息。相比持续改写前部 system prompt，这种安排能保留更多已发送历史作为可复用前缀；实际缓存行为依 provider 和模型而异，参见 [OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching) 与 [Anthropic Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)。

同一运行的内部步骤沿用入口背景，不在每轮工具执行后重新组装或重复注入语境。运行中的工具仍可读取空间当前内容，后续请求再取得新的语境视图。

会话适配层比较模型工作视图中的最近一份完整语境快照与本次视图，内容相同时复用，发生变化或缺少完整快照时追加。判重基于实际参与模型输入的视图，不以“历史里曾经出现过”或独立保存的注入标记作为复用条件。新建、恢复会话、切换分支或 compaction 后发起请求时，都重新作此判定。Session JSONL 保存交流和语境快照，空间中的持久表示仍拥有当前语境。

## 压缩与恢复

Pi 压缩会话后，适配层根据当前分支的压缩边界和既有消息记录，取得压缩时生效的最近一份完整语境快照。若该快照已退出保留消息，通过 `context` 事件在压缩摘要之后补入模型工作视图；边界之后的新快照仍按原消息顺序生效。这种补入只构造输入视图，保持同一压缩边界内的位置稳定，复用 Pi 的继续执行机制，不改写既有记录或额外启动请求。入口判重和模型调用使用同一工作视图构造方式，避免后续请求移走补入的内容而再次破坏前缀。

空语境也是有效视图。清空持久语境后，以明确的空快照更新先前的背景，旧快照保留为历史。读取或组装失败与空语境区分：语境模块报告准备错误，运行调度保留请求供重试，准备失败不得静默替换成旧视图或空视图。

语境消息明确标识为来自空间的持久背景；当前用户要求、用户偏好、来源内容与模型推断保留各自含义，缓存布局不改变其权威关系。视图生成保持确定的内容和格式，避免将无关的时间戳等变化带入模型输入。Pi 继续承担 provider 缓存参数与用量的适配，Repa 依据实际缓存用量、输入量和延迟评估接入效果。
