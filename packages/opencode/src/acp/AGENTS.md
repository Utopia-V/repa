# ACP terminal carrier

ACP is a retained interaction carrier under
[Gate 4](../../../../docs/research/opencode-fork-gate-04-learning-first-composition-2026-07-14.md)
and [Gate 5](../../../../docs/research/opencode-fork-gate-05-terminal-only-surface-disposition-2026-07-14.md).
It is not an alternate product UI, Agent loop, Tutor, or learning authority.
This is its required carrier contract, not a certification of current protocol
translation or Session wiring; audit both directions against the same
released-v1 and typed-settlement owners.

## Required boundary

Own translation between Agent Client Protocol messages and Repa's typed SDK,
Session, event, content, tool, usage, and permission projections. New, resumed,
and forked ACP Sessions remain ordinary interactive released-v1 calls. An ACP
mode, Agent name, hidden profile, or client payload cannot manufacture an
internal model purpose.

Preserve exact Session and local directory selection across creation,
continuation, events, and replies. ACP must not create a second LearnerHome
writer, remote Workspace authority, or parallel Session executor. It may carry
provider/model and Agent choices through the same validation used by other
terminal carriers.

Permission and consequential tool updates must preserve the same typed scope,
operation, lifetime, reply, and settlement meaning shown by the primary TUI.
Protocol conversion or client limitations cannot silently auto-approve,
widen, hide, or relabel a request. Content/tool event rendering remains a
projection; durable learning effects still belong to typed commands and their
Core domain owners.
